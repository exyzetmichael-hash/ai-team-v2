Системные обёртки некоторых сессий говорят «develop on branch

не вопрос для пересмотра, если явно не попросят иначе.

## Устройство репозитория ↔ сервер — важно для деплоя

Два разных паттерна, не перепутать:

1. **`profiles/edith/SOUL.md`, `config.yaml`, `MORNING.md`, `EVENING.md`,
   `scripts/*.py`** — на сервере это **копии** в `~/.hermes/profiles/edith/`.
   Деплой: `git pull` в `~/ai-team-v2`, затем `cp` нужного файла в
   `~/.hermes/profiles/edith/`, затем рестарт (`hermes -p edith gateway
   restart` для конфига/SOUL, ничего не надо для одноразовых скриптов).
2. **`profiles/edith/web/`** (веб-интерфейс) — systemd-юнит
   `hermes-web-ui.service` запускает `server.py` **прямо из checkout'а**
   `~/ai-team-v2/profiles/edith/web/server.py` (см. `ExecStart` в
   `ops/hermes-web-ui.service.template`). Деплой — **только** `git pull` +
   `systemctl --user restart hermes-web-ui`, копировать никуда не нужно.

Секреты — только в `~/.hermes/profiles/edith/.env` и `*.json`-конфигах
(`finance_webhook.json`, `web_ui.json`) на сервере, никогда в git (см.
`.gitignore` — там прямо перечислено, что именно не должно утечь).

У Михаила есть прямой SSH на сервер, он выполняет команды сам и присылает
вывод. Если SSH ломается (уже бывало дважды — см. `edith-full-brief.md`,
раздел 6) — у EDITH есть собственный `terminal`-тулсет (без sudo-пароля),
можно просить её продиагностировать через чат в Telegram.

## Паттерны, которых держимся (не придумывать заново)

- **Zero-LLM сторожа** (`mail_watchdog.py`, `politeh_schedule.py`,
  `budget_watchdog.py`) — `cron --script --no-agent`, регулярки вместо LLM
  там, где объём рутинный (сотни операций/писем) и цена ошибки парсинга
  терпима. Пустой stdout = тишина, ноль стоимости.
- **Деньги и даты периодов — всегда явный `Europe/Moscow`**
  (`MONEY_TZ = ZoneInfo(...)`), никогда пояс сервера (CEST) и никогда
  профильный `timezone:` EDITH — это разные вещи, путали уже дважды.
- **Cron с таймзоной — главная найденная ловушка проекта.** Смена ключа
  `timezone:` в конфиге НЕ пересчитывает уже существующие cron-задачи с
  абсолютным временем срабатывания. При любой смене пояса — пересоздавать
  («cron remove» + «cron create», не «cron delete» — такой подкоманды нет)
  каждую задачу по времени суток, не интервальную.
- **Документация с решениями, а не просто с фактами.** В `docs/*.md` всегда
  дописывается «почему», особенно отклонённые альтернативы (см. любой файл
  — паттерн «рассмотрено и отклонено: …») — следующей сессии (в т.ч. этой)
  не придётся передумывать то же самое заново.
- **Перед большим новым куском — план и подтверждение**, не сразу код.
  Михаил явно обозначает рамки («давай делаем» / «погодь, сначала…») —
  предлагать варианты через `AskUserQuestion`, когда неоднозначно, а не
  гадать и потом переделывать.
- **Коммиты — без упоминания модели/Claude в теле, только в `Co-Authored-
  By`.** Сообщение коммита — что и зачем, не «я сделал Х».
- **SOUL.md важнее скилла.** Скиллы Hermes не обязательны к прочтению
  моделью (см. инцидент с `research` в `edith-full-brief.md`) — жёсткие
  правила держать в `SOUL.md`, он всегда в системном промпте.
