# Брифинг сабагента

Текст ниже копируется в `delegate_task` как есть, с подстановкой `{{ПОДЗАПРОС}}` и
`{{ИСХОДНЫЙ_ВОПРОС}}`. Не переписывай своими словами — формат ответа парсится скриптом,
свободная форма его сломает.

---

## Текст задания

```
Ты ищешь факты по одному узкому подзапросу. Не отвечай на вопрос целиком — только собери
проверяемые факты по своей части и верни их в строгом JSON.

ПОДЗАПРОС: {{ПОДЗАПРОС}}
ОБЩИЙ КОНТЕКСТ (для понимания, что релевантно): {{ИСХОДНЫЙ_ВОПРОС}}

ЧТО ДЕЛАТЬ:

1. Выполни веб-поиск по подзапросу. Если выдача мусорная — переформулируй один раз и повтори.
   Больше двух попыток не трать.

2. Из выдачи выбери 2-4 самых релевантных результата. Критерии выбора:
   - первоисточник лучше пересказа (сайт компании > новость о компании > агрегатор)
   - официальное лучше блогового (документация, госсайт, отчёт > личный блог)
   - свежее лучше старого, если тема меняется во времени
   - пропускай: SEO-помойки, сайты-агрегаторы без своего контента, страницы с одним абзацем
     и десятью рекламными блоками

3. ОБЯЗАТЕЛЬНО открой выбранные страницы целиком, не работай по сниппетам из выдачи.
   Сниппет — это две строки, вырванные из контекста, и он регулярно врёт: обрезает отрицание,
   теряет условие «при таких-то обстоятельствах», показывает старую цифру из шапки страницы.
   Это главная причина, почему обычный поиск ошибается, а нормальный ресёрч — нет.

   **Чем открывать: `browser_navigate` + `browser_snapshot`, не `terminal`.**
   agent-browser отдаёт компактное accessibility-дерево вместо сырого HTML — на порядок
   меньше токенов на страницу и не требует парсинга. Раньше без него страницы приходилось
   тащить через `terminal` (`requests` + regex), это было и хрупко (JS-страницы отдавали
   пустой html, вёрстка менялась — regex ломался молча), и дорого по токенам (сырой HTML
   в контекст). Не пиши руками python-скрипты на `requests`/`BeautifulSoup` для чтения
   страницы — это шаг назад к тому, что чинили. `terminal` для этой задачи не нужен вообще.
   Если `browser_navigate` не поднимает страницу (капча, платный доступ, сайт блокирует
   headless) — пропусти страницу и возьми следующую из выдачи, а не выкручивайся через shell.

4. Из прочитанного вытащи конкретные факты. Факт — это утверждение, которое можно проверить:
   цифра, дата, название, условие, ограничение. Не факт: «эксперты считают», «многие
   отмечают», общие рассуждения без конкретики.

5. Для каждого факта запиши точный URL страницы, где он написан, и дату публикации или
   обновления, если она указана на странице.

ЧЕГО НЕ ДЕЛАТЬ:

- Не добавляй факты из своей памяти. Вообще. Даже если уверен, даже если это общеизвестно.
  В этот JSON попадает только то, что ты прочитал на странице по конкретному URL. Твоя память
  может быть устаревшей, и здесь её проверить некому.
- Не округляй и не пересчитывай цифры. Написано 12 400 — пиши 12 400, не «около 12 тысяч».
- Не приписывай факт с одной страницы URL другой страницы.
- Не пиши выводов и рекомендаций. Твоя работа — сырьё, выводы сделает родительский агент.

ФОРМАТ ОТВЕТА — только JSON, без markdown-обёртки, без текста до и после:

{
  "subquery": "твой подзапрос",
  "findings": [
    {
      "claim": "конкретный факт одним предложением",
      "url": "https://точный-урл-страницы",
      "title": "заголовок страницы",
      "date": "2026-06-12",
      "confidence": "high",
      "verbatim": false
    }
  ],
  "notes": "что не получилось найти, если что-то не получилось"
}

ПОЛЯ:
- date — в формате YYYY-MM-DD. Если на странице только месяц — YYYY-MM. Если даты нет вообще
  — null. Не угадывай дату по содержанию.
- confidence — "high" если факт прямо написан на странице недвусмысленно; "medium" если он
  следует из текста, но сформулирован тобой; "low" если страница выглядит сомнительно или
  информация подана вскользь.
- verbatim — true, если claim это близкая к тексту цитата (тогда держи её короткой, до 15
  слов); false, если ты переформулировал своими словами. По умолчанию переформулируй.

Если не нашёл ничего годного — верни findings: [] и объясни в notes, что именно не нашлось.
Пустой результат — нормальный результат. Выдуманный — нет.
```

---

## Как раскидывать подзапросы

Все `delegate_task` уходят **параллельно**, одним пакетом. Последовательный запуск
превращает 20 секунд в две минуты без всякой пользы.

Исключение: если один подзапрос зависит от результата другого («узнать текущую версию X» →
«что нового в версии X»), запускай во второй волне. Таких случаев мало, не выдумывай их без
необходимости.

## Что делать с ответами

Собери JSON-ы всех сабагентов в один файл `findings.json` — просто массив из их ответов:

```json
[
  { "subquery": "...", "findings": [...], "notes": "..." },
  { "subquery": "...", "findings": [...], "notes": "..." }
]
```

Если сабагент вернул невалидный JSON (бывает) — попробуй вытащить объект из текста. Если не
выходит, отбрось этот результат и отметь потерю. Не чини руками, дописывая недостающие поля
от себя: дописанное поле — это выдуманное поле.

Дальше — `python scripts/sources.py findings.json`.
