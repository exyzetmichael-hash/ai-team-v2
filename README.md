# ai-team-v2

Персональный ИИ-ассистент **EDITH** на базе [Hermes Agent](https://github.com/NousResearch/hermes-agent) v0.19.0.
Один агент, один Telegram-бот, одна память — специализация (память/vault, финансы, право,
учёба, трекинг проектов, ресёрч) живёт внутри него самого, не как отдельные боты.

> **Техническим специалистам:** полное описание проекта — архитектура, принятые решения с
> обоснованиями, найденные подводные камни и честный список ограничений — в
> **[`docs/project-overview.md`](docs/project-overview.md)**.

> Первая версия проекта (фазы 0-6) была «офисом» из семи отдельных ботов-личностей с
> координацией через Kanban. Технически работало, но не подошло по формату — переписано в
> единого ассистента. См. `profiles/README.md` за подробностями разворота.

## EDITH

| Профиль | Роль | Статус |
|---|---|---|
| `edith` | время/календарь/Todoist, память (Obsidian vault), личные финансы + право/учёба/трекинг-проектов/ресёрч как внутренние умения | 🚧 строится |

Маркетплейс WB/Ozon (главный бизнес-приоритет, ~сентябрь) — **не отдельный агент**, а
инструменты Seller API + скилл внутри EDITH. Решения и проверенные факты:
[`docs/marketplace-notes.md`](docs/marketplace-notes.md).

## Принципы

- **Не писать инфраструктуру агентов самому.** Берётся зрелый фреймворк, а собственный код —
  только надстройка: персона, конфиг, интеграции. Ядро Hermes не патчится, чтобы обновления
  не ломали систему.
- **Один голос, не диспетчер.** Специализация — внутренняя (`delegation`, fork/join
  сабагенты), не отдельные боты. Урок первой версии: правильная реализация неправильной идеи
  всё равно не подходит.
- **Мягкие лимиты вместо жёстких.** Бюджет-хук предупреждает, но архитектурно не может
  заблокировать запрос — решение всегда за владельцем.
- **Молчание — валидный ответ.** Утренняя сводка не приходит, если сказать нечего.
- **Дёшево по умолчанию, дорого точечно.** Дешёвая модель по умолчанию; апгрейд там, где
  цена ошибки высока (в первую очередь — арифметика по деньгам).
- **Проактивность без лишних сообщений.** Финансы — видно на панели/в таблице, не только по
  запросу; но решения (деньги, подписи) — всегда с явным «да» от владельца.
