# Фаза 1 — Runbook: поднять секретаря на VPS

**Цель фазы:** один живой агент-секретарь на CheapVibeCode. Дать ему ту задачу «поставь дедлайн», что падала за 90 с на старом ai-team. Замерить три вещи: **работает / сколько стоит / виден ли прогресс.**

Это go/no-go для всего проекта. Не поднимаем офис на пятерых, пока один секретарь не докажет, что он реально удобен.

---

## Кто что делает

- **Я (в репо):** характер секретаря (`profiles/secretary/SOUL.md`), шаблон конфига (`profiles/secretary/config.yaml`), шаблон секретов (`profiles/.env.example`), этот runbook.
- **Ты (на VPS):** всё, что ниже. Я на твоём VPS команды выполнить не могу — только даю их и кладу файлы в репо, ты подтягиваешь.

Значок 🟢 — делаешь ты на VPS. 📄 — файл берётся из этого репозитория.

---

## Что понадобится заранее

1. **VPS** с Ubuntu 22.04+. Доступ по SSH.
   - Проверенное железо старта: AdminVPS Lite (1 vCPU, 1 ГБ RAM, 15 ГБ NVMe, Ubuntu 24.04), 299 ₽/мес — для одного лёгкого секретаря ОК.
   - ⚠️ **RAM — узкое место.** На 1 ГБ обязателен swap (см. шаг 0). Весь офис (кодер+песочница, несколько агентов, веб-дашборд) на 1 ГБ не поедет — тариф бампим, когда реально упрёмся, не раньше.
2. **Данные CheapVibeCode:** base_url (вида `https://.../v1`), API-ключ, и точное имя модели, которое ты проверял (по брифу — `gpt-5.6`).
3. **Telegram-бот секретаря:** в @BotFather → `/newbot` → получишь токен. И свой Telegram user id — узнать у @userinfobot.

> Пока нет VPS — можно прогнать шаги 1–4 (установка + CLI-чат) даже на своём Linux/Mac/WSL, чтобы пощупать. Но для «работает всю ночь» нужен именно VPS.

## Шаги

### 🟢 0. Добавить swap (обязательно на 1 ГБ RAM)
Без swap агент на пике словит OOM и будет убит системой. Одноразово:
```bash
sudo swapon --show
grep -i swap /etc/fstab
free -h
```
Некоторые образы (например AdminVPS Ubuntu 24.04) уже ставят небольшой своп (~512 МБ) по умолчанию. Если `swapon --show` уже показывает файл — не пересоздавай его, а **добавь ещё один**, чтобы в сумме получить ~2 ГБ:
```bash
sudo fallocate -l 1536M /swapfile2
sudo chmod 600 /swapfile2
sudo mkswap /swapfile2
sudo swapon /swapfile2
echo '/swapfile2 none swap sw 0 0' | sudo tee -a /etc/fstab
free -h        # в строке Swap должно быть суммарно ~2.0Gi
```
Если `swapon --show` пустой (свопа нет вообще) — создавай с нуля на 2 ГБ:
```bash
sudo fallocate -l 2G /swapfile && sudo chmod 600 /swapfile && sudo mkswap /swapfile && sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
free -h
```

### 🟢 1. Установить Hermes
SSH на VPS, затем:
```bash
curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash
source ~/.bashrc
hermes doctor        # проверка, что всё встало
```
Если `install.sh` не качается (DNS/блокировки — у тебя такое было на Windows): склонируй репозиторий через github.com и поставь из чекаута по инструкции для контрибьюторов. На Linux-VPS это обычно не нужно, DNS там чистый.

### 🟢 2. Подключить провайдера (CheapVibeCode) и проверить голый чат
```bash
hermes setup
```
- Выбери режим **Blank Slate** (минимальный агент — всё лишнее выключено, ровно под наш лёгкий старт).
- Провайдер → **Custom endpoint** → введи `base_url`, API-ключ, имя модели (`gpt-5.6`).

Затем проверь, что базовый чат вообще работает (правило Hermes: не навешивать фичи, пока один чистый диалог не заработал):
```bash
hermes
```
Напиши ему что-нибудь простое («привет, посчитай 2+2 и скажи, какая ты модель»). Должен ответить без ошибок. Если пусто/мусор — `hermes model` заново, проверь base_url и имя модели. **Дальше не идём, пока этот шаг не зелёный.**

### 🟢 3. Создать профиль секретаря
```bash
hermes profile create secretary
```
Это заведёт `~/.hermes/profiles/secretary/` — отдельный дом со своей памятью и конфигом.

### 🟢📄 4. Залить характер и конфиг секретаря из репо
Подтяни этот репозиторий на VPS (`git clone` / `git pull`), потом скопируй файлы в профиль:
```bash
# из корня репозитория ai-team-v2:
cp profiles/secretary/SOUL.md    ~/.hermes/profiles/secretary/SOUL.md
cp profiles/secretary/config.yaml ~/.hermes/profiles/secretary/config.yaml

# секреты (Telegram) — из шаблона, ВПИСАТЬ реальные значения руками:
cp profiles/.env.example ~/.hermes/profiles/secretary/.env
nano ~/.hermes/profiles/secretary/.env   # вписать токен бота и свой TG id
```
Затем в `~/.hermes/profiles/secretary/config.yaml` замени `<CHEAPVIBECODE_BASE_URL>`, `<MODEL_ID>` и `<CHEAPVIBECODE_API_KEY>` на свои.

⚠️ **Ключ провайдера — прямо в `config.yaml` (`model.api_key`), не в `.env`.** Для `provider: custom` Hermes читает API-ключ только оттуда; `OPENAI_API_KEY` в `.env` подхватывается лишь встроенным провайдером `openai-api` и для CheapVibeCode не работает. Если пропустить это — получишь на первом запросе зависание на ~180с, а на ретрае `HTTP 401 Invalid API key` (проверено на практике). Проще всего не редактировать файл руками, а прогнать `hermes -p secretary model` — мастер сам корректно впишет `provider`/`base_url`/`api_key` в нужное место.

Проверь, что секретарь отвечает и характер подхватился:
```bash
hermes -p secretary
```
Спроси «кто ты и чем занимаешься» — должен ответить как секретарь Михаила, коротко.

### 🟢 5. Включить нужные секретарю инструменты
Секретарю нужны: **память, напоминания (cron), поиск по прошлым сессиям, лёгкий веб, задачи (todo).** Тяжёлое (шелл, код, браузер) в его конфиге уже выключено.
```bash
hermes -p secretary tools     # включи: memory, cronjob, session_search, web, todo, skills
```
Проверь напоминания на живом примере — это и есть та задача, что падала на старом ai-team:
```bash
hermes -p secretary
```
> «Поставь напоминание: сдать курсовую в пятницу в 18:00, и напомни мне за день.»

Секретарь должен показать, что делает («ставлю напоминание…»), и подтвердить. Если получилось за разумное время и без таймаута — **первый и главный симптом старой системы вылечен.**

### 🟢 6. Подключить Telegram (второй вход + доставка напоминаний)
```bash
hermes -p secretary gateway setup     # выбрать Telegram, вставить токен бота, allowlist = твой id
hermes -p secretary gateway start
hermes -p secretary gateway status
```
Теперь напиши боту в Telegram то же самое про дедлайн — должен ответить там. Напоминание в назначенное время должно прийти в Telegram само.

### 🟢 7. Замерить стоимость и кэш (ключевой замер фазы)
В сессии секретаря:
```bash
/usage        # сколько токенов/денег ушло
/insights --days 1
```
Проверка кэша: отправь **один и тот же** содержательный запрос два раза подряд и сравни в `/usage` число входных токенов и цену второго прогона. Если у CheapVibeCode кэш работает — второй раз входные токены/цена заметно ниже. Запиши цифры — по ним решаем вопрос модели и бюджета.

### 🟢 8. (Опционально, для «всю ночь») автозапуск gateway
Чтобы секретарь жил после выхода из SSH:
```bash
hermes -p secretary gateway start     # gateway уже умеет держаться как сервис (systemd/pid)
hermes -p secretary gateway status
```
Календарь (Google Calendar через MCP) подключим отдельным шагом после того, как база стабильна — он не нужен для проверки «поставь дедлайн».

## Что считаем успехом фазы 1

- [ ] Секретарь ставит напоминание без таймаута (лечение симптома №1 старой системы).
- [ ] Видно, что он делает в процессе (требование «наблюдаемость»).
- [ ] Он доступен и из CLI, и из Telegram; напоминание приходит само.
- [ ] Есть цифры по стоимости одной задачи и понятно, работает ли кэш.

Как соберёшь эти галочки — возвращаемся, смотрим цифры и решаем: докручивать секретаря (календарь, утренняя сводка) или сразу заводить второй мозг + vault.

## Если что-то ломается
Порядок восстановления (из доков Hermes): `hermes doctor` → `hermes model` → `hermes setup` → `hermes sessions list` → `hermes gateway status`.
