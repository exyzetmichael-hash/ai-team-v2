# Фаза 6 — Runbook: веб-доступ (нативный дашборд Hermes)

**Решение:** используем встроенный `hermes dashboard` (Hermes v0.19.0), а не сторонний UI
(hermes-webui/hermes-studio/hermes-workspace) и не свой фронт с нуля. Обоснование — ниже,
перед шагами.

---

## 0. Почему нативный дашборд, а не «свой» или сторонний

При планировании фазы 6 предполагалось, что придётся либо ставить сторонний UI
(hermes-webui/hermes-studio), либо писать свой фронт поверх `api_server` + SSE. По факту
обновления знаний о Hermes до v0.19.0 выяснилось, что сам Hermes уже включает готовый веб-
дашборд, который закрывает всё, что нужно по брифу, без дополнительного кода с моей стороны:

- **Один процесс на машину, обе роли.** Дашборд — machine-level: один сервер видит все
  профили (`secretary`, `brain`), переключатель профиля в сайдбаре меняет, какой профиль
  редактируют страницы Config/API Keys/Skills/MCP/Models/Chat. Не нужно поднимать два сайта.
- **Chat-вкладка = полноценный TUI в браузере**, включая resume существующих сессий — закрывает
  «веб-чат» из критерия готовности фазы напрямую.
- **Kanban-вкладка** — визуальные карточки задач между агентами (после фазы 5). Закрывает
  «карточки задач».
- **Analytics-вкладка** — расход по дням/моделям. Закрывает пункт бюджета из целей проекта
  («видно накопленный расход», уже частично закрыт budget-guard, тут — наглядно и по истории).
- **Sessions/Logs** — то, что раньше пришлось бы городить самому для отладки «что агент делал
  ночью».
- Сторонние UI (hermes-webui, hermes-studio) при этом не исчезают как опция — они остаются
  валидным запасным вариантом, если нативный дашборд после реального использования не устроит
  по вкусу/фичам (например, hermes-studio под BSL-1.1, но лицензия явно разрешает личное
  некоммерческое использование — проверено по тексту лицензии). Но начинать стоит с того, что
  уже в комплекте и поддерживается апстримом — меньше поверхности для поломки при `hermes update`.

**Утренний экран отдельным приложением не нужен** — то, что должно было им стать (сводка
дня, дедлайны, что сделано ночью), уже приходит текстом в Telegram по утреннему cron'у
(фаза 2) и доступно в Sessions/Analytics дашборда для просмотра истории. Если после реального
использования захочется отдельный экран-сводку — это узкая доработка (кастомная страница
плагином, см. `extending-the-dashboard.md`), не блокер для фазы 6 сейчас.

## 1. Предпосылки

Chat-вкладка дашборда — это встроенный TUI внутри браузера, ему нужен POSIX PTY:
```bash
cd ~/.hermes/hermes-agent
uv pip install -e ".[web,pty]"   # или ".[all]", если ставили так и раньше
```
(Contabo-сервер — Linux, POSIX PTY есть из коробки, отдельно проверять не нужно.)

## 2. Доступ: Tailscale + username/password, не публичный интернет

Дашборд читает и пишет твой `.env` (ключи, секреты) и может исполнять команды агента — **не
выставляй его в открытый интернет**. Вариант, который рекомендует сама документация Hermes
для homelab/VPS-сценария (наш случай) — Tailscale + встроенный username/password-провайдер:

1. Поставь Tailscale на сервер и на телефон/ноутбук, с которых будешь заходить:
   `https://tailscale.com/download` (бесплатный tailnet на личное использование хватает).
2. Узнай tailscale-IP сервера: `tailscale ip -4`.
3. Секреты в `~/.hermes/.env` (общий файл, не профильный — дашборд машинного уровня):
   ```bash
   cat >> ~/.hermes/.env <<'EOF'
   HERMES_DASHBOARD_BASIC_AUTH_USERNAME=<придумай логин>
   HERMES_DASHBOARD_BASIC_AUTH_PASSWORD=<придумай сильный пароль>
   HERMES_DASHBOARD_BASIC_AUTH_SECRET=<openssl rand -base64 32>
   EOF
   chmod 600 ~/.hermes/.env
   ```
   `..._SECRET` — обязательно постоянное значение, иначе после каждого рестарта дашборда
   придётся логиниться заново (ключ подписи сессии перегенерируется при старте, если его нет).

## 3. Автозапуск сервисом (переживает logout/reboot)

Сначала узнай реальный путь до `hermes` — **не полагайся на `PATH` внутри unit-файла**,
systemd запускает сервисы с минимальным `PATH`, который обычно не включает
`~/.local/bin`/pipx/uv-каталоги, где реально лежит `hermes`, даже если в интерактивном
шелле команда находится:
```bash
which hermes
```

```bash
sudo tee /etc/systemd/system/hermes-dashboard.service <<EOF
[Unit]
Description=Hermes web dashboard
After=network.target

[Service]
Type=simple
User=<твой linux-юзер>
EnvironmentFile=/home/<твой linux-юзер>/.hermes/.env
ExecStart=$(which hermes) dashboard --host <tailscale-ip> --port 9119 --no-open
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl daemon-reload
sudo systemctl enable --now hermes-dashboard
sudo systemctl status hermes-dashboard
```
(Подставь реального linux-юзера и tailscale-IP из шага 2 — жёстко зашивать `0.0.0.0` не
надо, это открыло бы порт на все интерфейсы, включая публичный, если фаервол не прикрывает.
Если `sudo tee` выполняешь не из-под того же пользователя, чей `which hermes` тебе нужен —
подставь путь руками вместо `$(which hermes)`.)

## 4. Проверка

Со своего устройства **в том же tailnet'е** (не с самого сервера):
```bash
curl -s http://<tailscale-ip>:9119/api/status | jq '.auth_required, .auth_providers'
# должно быть: true  ["basic"]
```
Если `auth_required: false` — гейт не включился, скорее всего username/password не попали в
окружение процесса (проверь `EnvironmentFile` в unit и что переменные реально в `.env`).

Дальше открой `http://<tailscale-ip>:9119` в браузере на телефоне/ноутбуке (Tailscale должен
быть подключён на этом устройстве) → Sign in → должен появиться дашборд с переключателем
профиля в сайдбаре. Переключатель строится сканированием `~/.hermes/profiles/` (`/api/profiles`)
— увидишь все семь (`secretary`, `brain`, `finance`, `tutor`, `tracker`, `research`, `legal`)
без дополнительной настройки.

## 5. Что проверить внутри

- [ ] **Chat** — открой чат с `secretary`, задай вопрос, сравни с тем же в Telegram —
  должна быть та же личность (SOUL.md общий, это один и тот же профиль).
- [ ] **Переключатель профиля** — переключись на любого из остальных шести, убедись что
  Config/Skills/Chat показывают именно его (амбер-баннер должен называть управляемый профиль).
- [ ] **Kanban** — вкладка показывает карточки офиса (фаза 5 уже включена всем семи) — те же,
  что видны через `hermes -p secretary kanban list`.
- [ ] **Analytics** — за 7 дней виден расход, помогает сверяться с budget-guard из фазы 2.
- [ ] **Sessions/Logs** — видно историю ночных cron-сводок секретаря и рабочих сессий остальных.

## 6. Hermes Desktop (опционально, если хочешь нативное приложение, а не браузер)

Не обязательно, браузер по Tailscale-адресу уже полностью рабочий вариант. Если хочется
нативного приложения на ноутбуке/телефоне — тот же дашборд можно открыть как «remote backend»
в Hermes Desktop (Settings → Gateway → Remote gateway → Remote URL `http://<tailscale-ip>:9119`
→ Sign in тем же логином/паролем). Сам дашборд поднимать отдельно не нужно — Desktop просто
подключается к уже работающему сервису из шага 3.

## Критерии готовности фазы 6
- [ ] Дашборд живёт как systemd-сервис, доступен по Tailscale-адресу, недоступен из открытого
  интернета.
- [ ] Вход защищён username/password, `HERMES_DASHBOARD_BASIC_AUTH_SECRET` зафиксирован (не
  разлогинивает при рестарте).
- [ ] С телефона/ноутбука по Tailscale открывается чат и видно обоих агентов через переключатель
  профиля.
