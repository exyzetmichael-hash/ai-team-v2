## Ответы на открытые вопросы (раздел 9 брифа)

### Q1/Q2 — Делегирование и mirror как примитив офис-шины

- `tools/delegate_tool.py`: делегирование оперирует **ролями `leaf` / `orchestrator`** (глубина/право дальше делегировать), а **не** адресацией к именованному профилю. Порождает анонимных сабагентов, наследующих конфиг родителя. Слово `profile` встречается в файле один раз. → делегирование это fork→join RPC внутри одного агента, не разговор между агентами-личностями.
- `gateway/mirror.py`: `mirror_to_session()` умеет записать сообщение в транскрипт **чужой** сессии (поиск по platform+chat_id, запись в SQLite). Но это только «положить в контекст» — агента **не будит**.

**Но нашлось лучшее.** `docs/.../kanban.md` + `plugins/kanban/`: **Hermes Kanban** — durable SQLite-board (`~/.hermes/kanban.db`), shared across all profiles. Именно то, что бриф в проблеме 6.1 считал нужным писать самим:

| | `delegate_task` | Kanban |
|---|---|---|
| Идентичность исполнителя | анонимный сабагент | **именованный профиль** с персистентной памятью |
| Координация | иерархия caller→callee | **peer** — любой профиль читает/пишет любую задачу |
| Human-in-the-loop | нет | комментарии / unblock в любой момент |
| Переживает рестарт | нет | да (durable rows) |

- Межагентный протокол — **тред комментариев** на задаче; при повторном спавне воркер читает весь тред как контекст.
- Диспетчер живёт **внутри gateway** (`kanban.dispatch_in_gateway: true`), каждые N сек промоутит/клеймит/спавнит назначенные профили.
- **Peer-модель без куратора = ровно схема «А» владельца** (раздел 5.5 брифа).

**Вывод:** офис-шину не пишем с нуля. Kanban закрывает «работу через границы агентов». Для разговорного офиса в группе (5.5) отдельно нужен гейт-хук — см. Q6.

### Q3 — CheapVibeCode как кастомный OpenAI-совместимый эндпоинт → ✅

`website/docs/integrations/providers.md`: Hermes работает с **любым** сервером, реализующим `/v1/chat/completions`, через провайдер `custom`:
```yaml
model:
  provider: custom
  base_url: https://<cheapvibecode>/v1
  api_key: <key>
  default: <model>
```
Есть **именованные** кастомные провайдеры (`/model custom:work:model`) — каждый профиль может смотреть на свой эндпоинт. Отдельно поддержан **LiteLLM-прокси** как OpenAI-совместимый шлюз с бюджет-контролем и фолбэком — прямой кандидат под мягкий лимит трат (Q10). `PROVIDER_REGISTRY` в `hermes_cli/auth.py` — 305 записей `base_url`, 18+ провайдеров подтверждены.

### Q4 — Общий слой памяти между изолированными профилями → ✅

`plugins/memory/` содержит 10 провайдеров: **honcho**, mem0, supermemory, byterover, hindsight, holographic, openviking, retaindb + инфраструктура. Все реализуют ABC `MemoryProvider` из `agent/memory_provider.py`; `initialize()` получает `hermes_home`.

**Honcho** даёт ровно гибрид из требования 3.4:
- **User peer — global across profiles** = общая база фактов о владельце (уровень 2 брифа);
- **AI peer — своя идентичность на каждый профиль** = личная память роли (уровень 3).
> «the user peer is global across profiles, each AI peer is its own identity… a `coder` profile stays code-oriented while a `writer` profile stays editorial against the same user».

Vault владельца (уровень 1) остаётся отдельно, через filesystem MCP + PR — как и планировалось.

### Q5 — Формат HOOK.yaml и сигнатуры → ✅

`gateway/hooks.py` + `docs/.../hooks.md`. Есть **три** системы хуков (бриф знал только про первую):

1. **Gateway hooks** — `~/.hermes/hooks/<name>/{HOOK.yaml, handler.py}`, `async def handle(event_type, context)`. **Только наблюдают**, только в gateway. События: `gateway:startup`, `session:*`, `agent:start|step|end`, `command:*`.
2. **Plugin hooks** — `ctx.register_hook(...)` в плагине, работают в CLI+gateway. **Часть умеет управлять потоком** (см. Q6).
3. **Shell hooks** — блок `hooks:` в config.yaml, любой язык, тоже умеют блокировать.

```yaml
# HOOK.yaml
name: my-hook
description: ...
events: [agent:step, agent:end]
```

### Q6 — Может ли хук отменить обработку? → ✅ ДА (load-bearing)

Через **plugin-хук `pre_gateway_dispatch`** — срабатывает на каждое входящее сообщение **до авторизации и до запуска агента**:

| Возврат | Эффект |
|---|---|
| `{"action": "skip", "reason": ...}` | сообщение отброшено, агент не запускается |
| `{"action": "rewrite", "text": ...}` | заменить текст и продолжить |
| `{"action": "allow"}` / `None` | обычная обработка |

Хук получает `event`, `gateway` (можно слать side-channel сообщения), `session_store` (можно тихо подшить чужую реплику в транскрипт). **Юзкейс из доков дословно:** «Listen-only group chats (only respond when tagged; buffer ambient messages into context)» — это буквально дешёвый гейт «моё/не моё» из раздела 6.2 брифа. Гейт стоит **до** дорогого цикла, а не после.

Также управляют потоком: `pre_tool_call` (блок тула), `pre_llm_call` (инъекция контекста), `pre_verify` (заставить агента продолжить). Всё остальное — observer-only.

### Q7 — api_server как бэкенд веб-UI → ✅

`gateway/platforms/api_server.py` — полноценный OpenAI-совместимый HTTP-сервер:
- `POST /v1/chat/completions`, `POST /v1/responses`, `GET /v1/models`, `GET /v1/capabilities`;
- сессии: `GET/POST/PATCH/DELETE /api/sessions[/{id}]`, `/messages`, `/fork`;
- **асинхронные раны со стримом событий:** `POST /v1/runs` → `run_id` (202), `GET /v1/runs/{id}/events` — **SSE-стрим структурированных lifecycle-событий**, `/approval`, `/stop`.
- **`gateway.multiplex_profiles`:** один листенер обслуживает все профили через префикс `/p/<profile>/v1/...`.

Это одновременно (а) бэкенд под наш дашборд, (б) источник «видно вызовы инструментов» (требование 3.6) через SSE, (в) **механизм пробуждения** профиля в шине — POST в `/p/<profile>/v1/...`.

### Q8 — Готовый веб-UI сообщества → ✅ есть, брать за основу

Зрелые проекты: **hermes-webui** (16k⭐), **hermes-studio** (дашборд, jobs, аналитика), **hermes-workspace** (chat/terminal/memory/skills/inspector), hermes-hudui. `api_server` отдаёт `/v1/capabilities` «for external UIs». → фронт с нуля не обязателен; в фазе 3 сначала оцениваем эти, потом решаем.

### Q9 — Кэш промптов вне Anthropic → ✅ (кэш у CheapVibeCode есть)

`agent/prompt_caching.py` — «Anthropic prompt caching strategy», layout `system_and_3`, 4 брейкпоинта `cache_control`. Доки: кэш авто-включается, «когда активный провайдер поддерживает». Адаптации: OpenRouter, Qwen (TTL 5 мин), Bedrock/Azure (дефолты провайдера), xAI (отдельный `x-grok-conv-id`). Отключить нельзя, always-on.

**Владелец подтвердил (2026-07-20): у CheapVibeCode кэширование есть.** Значит гроза бюджету (цикл на 18 раундов гоняет контекст заново) снята. В фазе 1 остаётся уточнить лишь **формат** кэша, чтобы Hermes слал правильные маркеры:
- если апстрим проксирует Anthropic и держит `cache_control` — работает нативный путь Hermes (`system_and_3`);
- если это OpenAI-style автоматический prefix-кэш — маркеры не нужны, кэш на стороне апстрима срабатывает сам по одинаковому префиксу (поэтому важна **стабильность системного промпта** — принцип Hermes соблюдён по дизайну).
Практический тест в фазе 1: два одинаковых запроса подряд, сверить `prompt_tokens` / cached-поля в ответе и цену. Если кэш не виден — проверить, каким API-режимом (`chat_completions` vs `anthropic_messages`) реселлер отдаёт кэш, и выбрать соответствующий.

## Как это меняет архитектуру (правки к разделам 5–6 брифа)

1. **Офис-шина → Kanban + гейт-хук.** Координация работы («секретарь передал финансисту») = Kanban (durable, peer, human-in-the-loop). Разговорный офис в группе = `pre_gateway_dispatch` (гейт «моё/не моё») + mirror (подшить чужие реплики в контекст). Своего движка шины писать не нужно.
2. **Гейт из раздела 6.2 — штатная точка расширения**, а не хак. Дешёвая классификация на самой дешёвой модели внутри `pre_gateway_dispatch`.
3. **Память из 3.4 — плагин Honcho**, а не самописный общий бэкенд.
4. **Веб (3.6) — сначала оценить готовые UI**, `api_server` даёт и данные, и стрим прогресса.
5. **Бюджет — LiteLLM-прокси перед CheapVibeCode** решает и мягкий лимит, и фолбэк, и наблюдаемость трат (кэш у CheapVibeCode уже есть).

## Остаточные риски (в порядке важности)

1. **Хостинг 24/7.** Kanban-диспетчер, несколько gateway-профилей, api_server, sandbox — нужен always-on хост (VPS / Modal / Daytona). Это статья расходов и ops, в потолке 3000 ₽ места мало. Решить рано.
2. **Разговорный офис требует калибровки гейта** на реальных сообщениях (чтобы не молчали/не отвечали все разом). Механизм есть, тюнинг — эмпирика.
3. **Быстрый апстрим** (16k коммитов): держимся плагинов/хуков/профилей, ядро не трогаем — тогда `hermes update` не ломает надстройку.
4. **Формат кэша CheapVibeCode** — какой API-режим отдаёт кэш; уточняется одним тестом в фазе 1 (см. Q9).
