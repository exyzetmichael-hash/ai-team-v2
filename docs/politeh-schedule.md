# Расписание Политеха → Google Calendar

Автоматический перенос пар из [ruz.spbstu.ru](https://ruz.spbstu.ru) в
отдельный календарь. Скрипт:
[`profiles/edith/scripts/politeh_schedule.py`](../profiles/edith/scripts/politeh_schedule.py).

**Ни одного вызова LLM.** Работает тем же паттерном, что сторож почты
(`cron --script --no-agent`): пустой stdout — полная тишина и ноль стоимости,
непустой — уходит в Telegram как есть. Уведомление приходит только когда
расписание реально изменилось, а не каждый прогон.

## Почему через API, а не браузером

У ruz есть открытый JSON API, скрейпить сайт не нужно:

```
GET /api/v1/ruz/search/groups?q=<номер группы>   # найти свою группу
GET /api/v1/ruz/scheduler/<group_id>?date=YYYY-MM-DD   # расписание на неделю
```

(база — `https://ruz.spbstu.ru/api/v1/ruz`). Это на порядок надёжнее
браузера: не ломается от смены вёрстки и не требует поднимать Chrome.

## Три решения, которые стоит знать

**Отдельный календарь, не primary.** Скрипт заводит календарь
«Политех — расписание» сам при первом запуске. Причина не косметическая:
синхронизация **удаляет** события, пропавшие из источника, и ошибка в
матчинге на основном календаре означала бы снос настоящих встреч. Плюс
страховка — трогаются только события со своей меткой в `extendedProperties`
и только внутри окна дат.

**Пояс задан явно (`Europe/Moscow`).** В задаче сходятся три разных пояса:
профиль EDITH до сих пор `Asia/Krasnoyarsk` (переезд конца августа 2026),
сервер в CEST, пары идут по Питеру. Брать пояс из системного времени —
гарантированные пары не в то время.

**Пустой ответ = ничего не делаем.** Каникулы и упавший ruz выглядят
одинаково — пустым списком. Стирать всё расписание из-за недоступного сайта
нельзя, поэтому при пустом ответе скрипт молча выходит, не удаляя ничего.

## Настройка

Сначала проверь, что ruz вообще доступен с сервера (европейский IP,
блокировка не исключена — как и с Seller API маркетплейсов):

```bash
curl -s -o /dev/null -w "%{http_code}\n" -m 20 https://ruz.spbstu.ru/api/v1/ruz/faculties
```

Не `200` — API с этого сервера не виден, нужен ру-прокси (та же
инфраструктура, что понадобится под WB/Ozon).

Дальше:

```bash
PY=~/.hermes/hermes-agent/venv/bin/python3
S=~/.hermes/profiles/edith/scripts/politeh_schedule.py

# 1. найти id своей группы
HERMES_HOME=~/.hermes/profiles/edith $PY $S --find-group <номер группы>

# 2. посмотреть, что получится — БЕЗ записи в календарь
HERMES_HOME=~/.hermes/profiles/edith $PY $S --group-id <id> --dry-run

# 3. если вывод сходится с сайтом — сохранить конфиг и синхронизировать
echo '{"group_id": <id>, "weeks_ahead": 2}' > ~/.hermes/profiles/edith/politeh_schedule.json
HERMES_HOME=~/.hermes/profiles/edith $PY $S
```

⚠️ Шаг 2 не пропускать. Точную схему ответа ruz живьём при написании
проверить не удалось (API недоступен из среды разработки), парсинг написан
защитно — кривое поле даёт пропуск пары с жалобой в stderr, а не падение.
`--dry-run` — это и есть проверка, что схема совпала.

## Крон

Раз в сутки достаточно: расписание правят по ходу семестра, но не ежечасно.

```bash
hermes -p edith cron create "every day at 07:00" \
  --script politeh_schedule.py --no-agent \
  --name "Расписание Политеха" --deliver telegram
```

(путь скрипта резолвится относительно `<HERMES_HOME>/scripts/`)

## Файлы состояния

| Файл (в профиле) | Что |
|---|---|
| `politeh_schedule.json` | конфиг: `group_id`, `weeks_ahead` |
| `politeh_schedule_state.json` | кэш id календаря — чтобы не искать перебором и не плодить второй календарь, если переименуешь руками |
