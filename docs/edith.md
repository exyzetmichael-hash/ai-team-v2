# EDITH — полное описание

Снимок состояния на 2026-07-30. Живой документ: правь его при каждом значимом изменении
EDITH, чтобы не пришлось потом собирать историю заново по коммитам.

---

## 1. Кто это

**EDITH** — единственный личный ИИ-ассистент Михаила. Один Telegram-бот
(`@edith_aiassist_bot`), один разговор, без переключения между «коллегами». Названа в честь
ИИ Тони Старка (*Even Dead, I'm The Hero*) — назначение то же: не инструмент, ждущий команды,
а помощник, который реально держит в поле зрения жизнь человека.

**Для кого.** Михаил — студент-фрилансер, готовится к переезду в Санкт-Петербург (конец
августа 2026, направление AI/ML). Живёт в режиме жёсткой экономии: нестабильный доход,
предстоящая аренда в новом городе. Сейчас в Красноярске (UTC+7). Интроверт — не любит каждый
раз формулировать запрос, чтобы посмотреть на положение дел; предпочитает, когда нужное само
на виду (панель/сводка), а не требует спросить.

## 2. Почему один ассистент, а не команда ботов

До EDITH пять фаз проекта строили «офис» — семь Telegram-ботов (секретарь, второй мозг,
финансист, юрист, тьютор, трекер задач, ресёрчер) с координацией через Kanban-доску и
гейт-хук, решающий, кто отвечает. Технически всё работало (тесты, живые прогоны, дашборд).
Не подошло **на практике**: формат «переписывайся с семью личностями по отдельности, следи
за темами, жди кто ответит» оказался лишним процессом, а не помощью. Живое обсуждение,
которое к этому привело, есть в истории проекта — коротко: специализация была нужна,
упаковка в виде отдельных ботов — нет.

Решение: схлопнуть семь профилей в один. Специализация никуда не делась — она живёт **внутри**
EDITH через `delegate_task` (anonymous fork/join сабагенты, `tools/delegate_tool.py`, роли
leaf/orchestrator, не именованные профили). EDITH сама уходит вглубь узкой темы и
возвращается с ответом — Михаил этого не видит, для него это один голос. Это тот же примитив,
что раньше рассматривался и был отложен в пользу Kanban (см. `phase-0-verification.md`,
Q1/Q2) — теперь он оказался ровно тем, что нужно.

Механика перехода — `phase-9-edith-runbook.md`.

## 3. Что умеет

### Время, задачи, календарь
- Google Calendar — через bundled-скилл `productivity/google-workspace` (OAuth,
  `--services calendar,sheets`). Создание/удаление события — не бесшумно, EDITH говорит, что
  делает, прежде чем сделать.
- **Todoist — единственный источник правды по задачам**, официальный MCP-сервер
  (`@doist/todoist-mcp`), из ~45 инструментов оставлено 9 нужных (find/add/update/complete/
  reschedule-tasks, find-projects, get-overview). Перенос срока — только через
  `reschedule-tasks`, не `update-tasks` (иначе ломается повторяемость).
- Утренняя сводка по cron (`MORNING.md`) — календарь + просроченные и сегодняшние задачи +
  заметное по деньгам за сутки. Если сказать нечего — молчит (`[SILENT]`), не пишет ради
  формы.

### Память
- Прямой доступ к Obsidian vault (`/home/michael/vault`) — как у Клода: читает, ищет,
  связывает по команде, не сканирует в фоне без запроса. Два MCP-сервера: `filesystem`
  (официальный `@modelcontextprotocol/server-filesystem`, read/write внутри vault) и
  `graphify` (граф знаний поверх vault — дешёвые структурные запросы вместо перечитывания
  сырых файлов на каждый вопрос, read-only).
- Пишет в vault **только через Pull Request** (скилл `vault-pr-write`), никогда напрямую в
  основную ветку — vault источник правды Михаила, PR даёт проверить и принять/отклонить.

### Деньги
- Ведёт Google-таблицу доходов/расходов — 7 листов (Операции, Категории, Регулярные
  платежи, Цели, Бюджеты, Долги, Сводка с графиками), полная структура и обоснование в
  [`finance-sheet-spec.md`](finance-sheet-spec.md). Это и есть «панель для взгляда без
  запроса» — таблица всегда актуальна, плюс раз в неделю EDITH присылает сводку сама.
- Показывает выкладки при расчётах, не только результат — ошибку видно сразу. Важные суммы
  пересчитывает второй раз.
- Проактивность в деньгах ограниченная: может молча обновлять таблицу и один раз спокойно
  отметить важное («на этой неделе ушло больше обычного, в основном на X»), но не советует и
  не решает за Михаила без запроса. Никаких рекомендаций по инвестициям — только учёт.

### Голос
- Голосовые сообщения в Telegram распознаются автоматически (STT встроен в гейтвей,
  специально звать инструмент не нужно). Провайдер — Groq (`whisper-large-v3-turbo`),
  бесплатный тариф без карты. Эхо сырой расшифровки в чат отключено — EDITH просто отвечает
  по содержанию.

### Узкие умения по запросу (не отдельные боты)
Право фрилансера (договоры, ИП/самозанятость), учёба (матан/линал/Python/алгоритмы/ML),
состояние проектов — подключаются сами через `delegate_task`, когда тема выходит за
разговорный уровень. Снаружи — всё тот же один голос.

### Ресёрч с проверяемыми источниками (скилл `research`)
Полноценный пайплайн поиска вместо «нагуглить и пересказать»: декомпозиция вопроса на 2–6
подзапросов → параллельные сабагенты через `delegate_task`, каждый **читает полные страницы**
(не сниппеты, которые обрезают отрицания и условия) → сведение через
`scripts/sources.py` (дедуп, вес источника = тип домена + свежесть + подтверждение другими +
уверенность, сквозная нумерация `[n]`, поиск противоречий) → ответ, где каждый факт стоит на
конкретной ссылке.

Три вещи, которых нет у Perplexity:
1. **Шаг 0 — сначала vault.** Прежде чем идти в веб, EDITH смотрит, не записан ли ответ уже
   в памяти Михаила. Расхождение vault и веба показывается явно, а не решается молча.
2. **Конфликты не прячутся.** Если источники дают разные числа — показываются обе версии с
   датами, без молчаливого выбора «более уверенно звучащего».
3. **Накопление.** Результат глубокого ресёрча предлагается сохранить в vault через
   `vault-pr-write` — Perplexity каждый раз ищет с нуля и всё забывает.

Режимы: `quick` (1 подзапрос), `standard` (2–4), `deep` (4–6). Файлы скилла —
`profiles/edith/skills/research/`.

⚠️ **Скиллы в Hermes необязательны к исполнению — это главное ограничение.** В системный
промпт попадает только компактный индекс (имя + описание); полную инструкцию модель должна
сама дочитать через `skill_view`. Механизма «всегда загружать скилл» в Hermes нет.

На первом живом прогоне (сравнение комиссий Ozon и WB) это и выстрелило: EDITH скилл **не
открывала**, вместо пайплайна сделала один общий `delegate_task` и скомпилировала отчёт.
Внешне ответ выглядел отлично — структура, эмодзи, уверенный вывод, — но без единого маркера
`[n]`, со списком источников голыми доменами без ссылок и с диапазонами вместо конкретных
чисел («10–15%»). То есть ровно то, что скилл создавался предотвращать, в самой опасной
форме: убедительно и непроверяемо.

Лечение — жёсткое правило в `SOUL.md` (он в системном промпте всегда, в отличие от скилла):
для любого вопроса с внешними фактами обязательно открыть `research` через `skill_view`,
плюс явный запрет на три уже случившихся способа срезать угол (ответ по памяти, одиночный
`delegate_task` вместо пайплайна, ответ без `[n]` и списка источников с URL).

Если и с этим правилом модель продолжит срезать — причина не в тексте, а в модели:
`deepseek-v4-flash` дёшева и склонна к короткому пути, а пайплайн тут в шесть шагов с
сабагентами, JSON и запуском скрипта. Тогда ресёрч нужно гонять на модели посильнее.

✅ **Проверено повторно после правки SOUL.md — заработало.** Второй прогон уже с маркерами
`[n]` и списком источников со ссылками. Заодно основную модель сменили насовсем: OpenAI
срезали цену на `gpt-5.6-luna` на 80% ($0.10/$0.60 за 1M на OpenRouter), дешевле
`deepseek-v4-flash` при том же tool-calling и контексте 1.05M — переключено через `/model
openai/gpt-5.6-luna --global` прямо из Telegram.

### Маркетплейс WB/Ozon — на подходе, не сейчас
Главный бизнес-приоритет (~сентябрь 2026), встроится инструментами Seller API + скиллом
внутрь EDITH, не отдельным профилем. Гео-доступ уже проверен с боевого сервера — блокировки
нет, российский прокси не нужен. Полный разбор — [`marketplace-notes.md`](marketplace-notes.md).

## 4. Технический профиль

| | |
|---|---|
| Модель | `openai/gpt-5.6-luna` через OpenRouter ($0.10/$0.60 за 1M — цену срезали на 80%, дешевле deepseek-v4-flash, контекст 1.05M). Запасная при 429 — `openai/gpt-5.4-mini` |
| Часовой пояс | `Asia/Krasnoyarsk` (UTC+7) — сменить на `Europe/Moscow` и **пересоздать cron-задачи** при переезде в Питер, конец августа 2026 |
| Подтверждения | `approvals.mode: manual` — ручное подтверждение по-настоящему опасных команд (есть полноценный `terminal` ради Google Workspace скрипта) |
| STT | Groq `whisper-large-v3-turbo`, эхо расшифровки выключено |
| Delegation | включена (единственное отличие от старых семи профилей — там её не было) |
| Разница CLI/Telegram | **нет** — одинаковый набор тулсетов на обеих площадках, сознательно (в старом офисе разные наборы толкали агента говорить «у меня нет такого инструмента» не по делу) |

**Отключённые тулсеты** (`agent.disabled_toolsets`, полный список, а не дополнение к
машинному — см. предупреждение в `config.yaml`): `code_execution`, `browser`,
`computer_use`, `image_gen`, `video`, `video_gen`, `x_search`, `kanban`, `discord`,
`discord_admin`, `feishu_doc`, `feishu_drive`, `homeassistant`, `spotify`, `yuanbao`,
`project`, `search`, `context_engine`.

**Включённые тулсеты** (`platform_toolsets`, одинаково на `cli` и `telegram`): `web`, `file`,
`memory`, `session_search`, `skills`, `todo`, `cronjob`, `clarify`, `tts`, `terminal`,
`vision`, `delegation`.

⚠️ **`delegation` в этом списке обязателен.** Когда перечислены конкретные тулсеты (а не
композит вроде `hermes-cli`), Hermes включает строго перечисленное. Без `delegation` нет
инструмента `delegate_task` — а на нём стоит и внутренняя специализация EDITH, и весь скилл
`research`. Поймано при разборе скилла: конфиг выглядел рабочим, но сабагентов физически
не существовало.

## 6. Решения, принятые по пути (и почему)

- **Composio — отклонён.** MIT покрывает только SDK, рантайм с кредами закрыт,
  самохостинг только по Enterprise-контракту. Все нужные EDITH сервисы (Calendar, Sheets,
  Todoist, vault) уже подключены напрямую и бесплатно — платная закрытая прослойка не решает
  задачу, которой нет.
- **Нативное мобильное приложение — отложено.** Telegram уже есть мобильный интерфейс;
  веб-дашборд свёрстан под мобильный (`viewport-fit=cover`) и добавляется на главный экран
  телефона как псевдо-приложение, хоть и не полноценный PWA (нет manifest/service worker).
  Решили пожить с этими двумя слоями, прежде чем разрабатывать нативный клиент поверх
  headless `hermes serve`.
- **Финансовая таблица спроектирована заранее на 12 вопросах**, а не как плоский список из
  5 колонок — переделывать структуру задним числом, когда там уже есть данные, дороже, чем
  спроектировать один раз. Результат — 7 листов, см. `finance-sheet-spec.md`.
- **Живые баги, пойманные при разводе EDITH** (оба исправлены, задокументированы в
  `phase-9-edith-runbook.md`, чтобы не повторить): (1) `disabled_toolsets` в профильном
  конфиге полностью заменяет машинный список, а не дополняет — `kanban` молча ожил, хотя
  нигде не упоминался; (2) гейтвей по умолчанию эхом шлёт сырую STT-расшифровку в чат
  отдельным сообщением — выключено через `stt_echo_transcripts: false`.
