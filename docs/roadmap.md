# ai-team-v2 — Дорожная карта до цели

Обновлено: 2026-07-25. **Фазы 1-3 и 8 развёрнуты и работают вживую:** секретарь (CLI +
Telegram, календарь, Todoist, утренняя сводка по cron, бюджет-хук) и второй мозг `brain`
(vault через git, запись только через PR, Graphify-граф, filesystem-MCP). Фаза 7 (пять новых
ролей) развёрнута владельцем. Артефакты фаз 5-6 готовы в репозитории, ждут разворачивания —
см. `docs/phase-N-runbook.md`. Фаза 4 (маркетплейсер) намеренно не трогалась — тестить пока
негде.

## Цели проекта (критерии успеха)

Из брифа, с поправкой на пивот «кодер → маркетплейсер» (владелец кодит с Claude Code,
поэтому кодер-агент снят с приоритета; маркетплейсер поднят в главные).

1. **Личный секретарь** — дедлайны, календарь, напоминания, утренние сводки. ✅ работает.
2. **Второй мозг** — работа с Obsidian vault, запись через PR, накопление знаний. ✅ работает.
3. **Маркетплейсер (WB/Ozon)** — главный бизнес-приоритет, старт ~сентябрь. Читает заказы/
   остатки/цены, предлагает действия, действует только по явному «да».
4. **Офис** — агенты видят друг друга и передают работу (Kanban) без куратора; в общем
   чате отвечает тот, кому тема ближе (гейт-хук).
5. **Проактивность** — утренние сводки и напоминания сами приходят в Telegram.
6. **Доступ отовсюду** — Telegram (есть) + веб-дашборд.
7. **Бюджет** — весь стек в пределах ~3000 ₽/мес; дешёвые модели на рутину, дорогие точечно.

8. **Расширение команды ролями** — финансист, тьютор, проджект-трекер, ресёрчер, юрист
   (выбраны Михаилом из списка предложений, см. фазу 7). Кодер снят с приоритета — Михаил
   кодит сам с Claude Code.

## Разделение труда (важно)

| Могу сам (в репо) | Только владелец (на сервере) |
|---|---|
| SOUL-персоны, конфиги профилей | Выполнить команды, `hermes ...` |
| Код хуков/плагинов, скиллы | Ввести ключи/токены, создать ботов |
| Cron-задания, шаблоны | Клики в веб-кабинетах, оплата |
| Пошаговые runbook'и под каждую фазу | **Живой тест и отладка** |

Всё «моё» готовится заранее; каждая фаза для владельца = «скопировал-запустил-проверил».

## Фазы

### Фаза 2 — Секретарь как ежедневный инструмент
Сделать уже работающего секретаря реально полезным каждый день.
- **Я готовлю:** cron-задание утренней сводки + скилл/промпт сводки; конфиг Google Calendar
  (MCP); хук мягкого бюджет-лимита (предупредить-и-спросить, не рубить); уточнённый SOUL;
  runbook подключения календаря.
- **Владелец делает:** подключает Google Calendar (OAuth), заводит cron, вводит ключи.
- **Готово когда:** утром в Telegram приходит сводка (или тишина, если нечего); дедлайны
  напоминают сами; календарь заполняется агентом; видно накопленный расход.

### Фаза 3 — Второй мозг + vault
- **Я готовлю:** SOUL «второго мозга»; конфиг профиля `brain`; filesystem-MCP на vault;
  скилл «запись в vault через PR»; runbook (vault → приватный git — git тут одновременно и
  синхронизация между компом владельца и сервером, и ревью перед записью). Память — три
  слоя: встроенная память Hermes (личная память роли `brain`, разговоры/факты — бесплатно,
  из коробки) + **Graphify** (граф знаний поверх содержимого vault, дешёвые структурные
  запросы вместо перечитывания файлов целиком — включили сразу, не отложенная опция) +
  общий факт-слой о владельце между профилями (Honcho) остался опциональным апгрейдом в
  runbook, не включён — с двумя профилями острой нужды делиться фактами пока нет.
- **Владелец делает:** заводит приватный git-репо под vault, подключает MCP, ключи.
- **Готово когда:** `brain` читает vault по команде и пишет в него только через PR;
  помнит проекты/сроки между сессиями.

### Фаза 4 — Маркетплейсер (главный приоритет, ~сентябрь)
- **Сначала тест:** с EU-сервера curl'ом проверить, доступен ли Seller API WB/Ozon
  (не блокируют ли EU-IP). Если блок — поднять лёгкий ру-прокси на AdminVPS и гнать
  только маркетплейс-трафик через него.
- **Я готовлю:** SOUL маркетплейсера; инструменты WB/Ozon Seller API (Python-тулы в реестр
  Hermes) — **черновик под живую проверку**; конфиг с обязательным подтверждением на любые
  действия (бизнес-режим = только по «да»); runbook ру-прокси.
- **Владелец делает:** API-ключи продавца, тест доступа, отладка тулов на реальных данных.
- **Готово когда:** читает заказы/остатки/цены; предлагает действия; выполняет только после
  явного подтверждения.

### Фаза 5 — Офис (агенты общаются)
Только когда есть ≥2 рабочих агента.
- **Я готовлю:** гейт-хук `pre_gateway_dispatch` (дешёвая классификация «моя тема / не моя»
  на самой дешёвой модели) — **черновик под проверку**; настройку Kanban (общая доска,
  передача задач между профилями); runbook общего Telegram-чата офиса.
- **Владелец делает:** заводит общий чат, разворачивает плагин, калибрует гейт на реальных
  сообщениях.
- **Готово когда:** агенты координируются через Kanban; в общем чате отвечает нужный, без
  куратора, без «все молчат / все разом».

### Фаза 6 — Веб-дашборд
- **Решение (по факту апдейта до v0.19.0):** свой фронт не пишем — у Hermes уже есть встроенный
  `hermes dashboard` (machine-level, обе роли через переключатель профиля, веб-чат = TUI в
  браузере, Kanban-вкладка, Analytics, Sessions/Logs). Сторонние UI (hermes-webui/hermes-studio)
  остаются запасным вариантом, если нативный не устроит по факту использования.
- **Я готовлю:** runbook (Tailscale + username/password провайдер + systemd-сервис, без
  выхода в публичный интернет).
- **Владелец делает:** ставит Tailscale, разворачивает сервис, заходит с телефона.
- **Готово когда:** веб-чат + Kanban-карточки + история/расход доступны с телефона по
  Tailscale, вход защищён паролем.

### Фаза 7 — Новые роли (финансист, тьютор, трекер, ресёрчер, юрист)
Выбраны Михаилом из списка предложенных ролей; остальные (спорт, здоровье, фриланс-менеджер,
контент, координатор поступления) отклонены как ненужные.
- **Я готовлю:** SOUL-персоны и конфиги профилей `finance`, `tutor`, `tracker`, `research`,
  `legal`; общий runbook разворачивания (один шаблон на все пять — они однотипные).
- **Принцип:** все пятеро — **лёгкие** агенты по образцу секретаря (память + переписка).
  Файловая система/vault остаётся **только у `brain`** — это принцип из брифа 3.3, и второй
  раз я его не ломаю (terminal у секретаря появился вынужденно, ради Google Calendar, см.
  фазу 2). Исключения, каждое обосновано: `research` и `legal` получают веб-поиск (без него
  роль бессмысленна), `tutor` — выполнение кода (разбор алгоритмов/задач).
- **Владелец делает:** создаёт профили, вводит ключ OpenRouter, живой тест.
- **Готово когда:** каждая роль отвечает по своей теме, не лезет в чужие, помнит контекст
  между сессиями.

### Фаза 8 — Todoist MCP для секретаря
- **Зачем:** у Михаила задачи живут в Todoist; секретарь должен читать/ставить их сам, а не
  держать параллельный список в своей памяти.
- **Решение:** официальный MCP-сервер от Doist (`@doist/todoist-mcp`, npm) в stdio-режиме.
  Своей интеграции с Todoist у Hermes нет (проверено по исходникам v0.19.0). Хостед-вариант
  по HTTP отпал — там OAuth через браузер, а сервер headless.
- **Я подготовил:** `mcp_servers.todoist` в конфиге секретаря с подстановкой `${TODOIST_API_KEY}`
  из `.env` (токен в git не попадает) и фильтром `tools.include` на 9 инструментов из ~45 —
  лишние схемы стоят токенов в каждом ходу и путают дешёвую модель при выборе инструмента;
  раздел про задачи в SOUL (Todoist — единственный источник правды, перенос срока только через
  `reschedule-tasks`, иначе ломается повторяемость); задачи в утреннем чеклисте `MORNING.md`;
  runbook `docs/phase-8-todoist-runbook.md`.
- **Владелец делает:** берёт токен в Todoist → Settings → Integrations → Developer, кладёт в
  `.env` профиля, живой тест.
- **Готово когда:** секретарь видит задачи из Todoist, ставит новые по просьбе, и утренняя
  сводка учитывает их наравне с календарём и дедлайнами.

## Сквозное (идёт всегда)
- **Бюджет:** мониторинг расхода, дешёвые модели на рутину/роутинг, дорогие точечно.
- **Бэкапы:** vault и конфиги профилей в git; периодический бэкап `~/.hermes`.
- **Безопасность:** allowlist только владельца, подтверждения на опасное, ключи не в git.
- **Апстрим:** держимся плагинов/хуков/профилей, ядро Hermes не трогаем — `hermes update`
  не ломает надстройку.

## Что «я работаю один» даёт и не даёт
- **Даёт:** весь репозиторий, забитый готовыми артефактами и runbook'ами под фазы 2-6,
  за один заход. Не «дни автономной стройки» — одна рабочая сессия.
- **Не даёт:** развёрнутого и протестированного на сервере результата. Деплой, ключи,
  оплата и живой тест — всегда за владельцем. Код плагинов (офис, маркетплейс-тулы) —
  черновики под проверку, т.к. я не могу их прогнать и сервер на более новом Hermes.
