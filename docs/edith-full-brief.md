# EDITH — полная карта проекта

Собрано 2026-09-08 из всей документации репозитория `ai-team-v2` и истории разработки —
для переноса во второй мозг / подготовки рассказа о проекте. Ничего не упрощено ради
краткости: если деталь была важна настолько, что попала в докстринг или коммит — она здесь.

---

## 1. Что это и для кого

**EDITH** — личный ИИ-ассистент Михаила: студент-фрилансер, поступил на AI/ML в вуз в
Санкт-Петербурге, переехал туда 2026-08-25 (до этого — Красноярск, UTC+7). Живёт в режиме
жёсткой экономии, доход нестабильный. Пишет код в связке с Claude Code сам — поэтому роль
«кодера» в команде агентов никогда не была нужна.

Названа в честь ИИ Тони Старка (*Even Dead, I'm The Hero*) — не косметика: заявленная планка
поведения — «Джарвис не ждал команды и не был сервисом, он был кем-то», подробнее в разделе 4.

Работает как один Telegram-бот (`@edith_aiassist_bot`) + CLI (`hermes -p edith`) + собственный
веб-интерфейс (раздел 5.8) — везде одна и та же личность, память, инструменты.

## 2. История: от «офиса» из семи ботов к EDITH

### v1 (`ai-team`) — провал, определивший весь v2
Самодельный Telegram-бот с нуля. Агенты переставали отвечать, память терялась, оркестрация
разъезжалась. **Вывод, определивший всю архитектуру v2: не писать инфраструктуру агентов
самому — взять зрелый фреймворк (Hermes Agent) и строить только надстройку.**

### v2, фазы 0-6 — «офис» из семи ботов-личностей
Секретарь (календарь, дедлайны, сводки) + `brain` (второй мозг, Obsidian vault через PR) +
finance/tutor/tracker/research/legal — семь отдельных Telegram-ботов с координацией через
Kanban-доску (`~/.hermes/kanban.db`, общая для всех профилей) и гейт-хук `office-gate`,
решающий, кто отвечает в общем чате. **Технически всё работало** (тесты, живые прогоны,
дашборд, ~30 коммитов, 8 runbook'ов) — но **не подошло на практике**: формат «переписывайся
с семью личностями по отдельности, следи за темами, жди кто ответит» оказался лишним
процессом, а не помощью.

Фаза 7 (пять новых ролей — финансист/тьютор/трекер/ресёрчер/юрист, выбраны Михаилом из
предложенного списка) и фаза 8 (Todoist MCP) были **развёрнуты и работали живьём** в этой
схеме до пивота.

### Пивот на EDITH (фаза 9, 2026-07-30)
Семь профилей схлопнуты в один. Специализация никуда не делась — она живёт **внутри** EDITH
через `delegate_task` (anonymous fork/join сабагенты, `tools/delegate_tool.py`, роли
leaf/orchestrator, не именованные профили) вместо Kanban-передачи между ботами. EDITH сама
уходит вглубь узкой темы (право, учёба, ресёрч, трекинг) и возвращается с ответом — Михаил
этого не видит, для него один голос.

Что перенеслось as-is: OpenRouter-ключ, Todoist-ключ, клон vault-репо, GitHub PAT.
Что построено заново: профиль, новый бот, OAuth с добавленным scope Sheets, финансовая
таблица.

**Живые баги пивота (оба найдены на первом запуске, оба исправлены):**
- `agent.disabled_toolsets` в профильном конфиге **полностью заменяет** машинный список
  (36 пунктов), а не дополняет — в конфиге было явно перечислено только 7 пунктов, и `kanban`
  молча ожил в «Available Tools», хотя офис уже снесён. Исправлено — список расширен до
  полного (см. раздел 6).
- Гейтвей по умолчанию эхом шлёт сырую STT-расшифровку в чат отдельным сообщением до ответа
  модели — выключено через `stt_echo_transcripts: false`.

### 2026-08-14 — vault убран
Изначальная схема (EDITH читает/пишет в Obsidian vault через PR, MCP `filesystem`+`graphify`)
не подошла Михаилу: **«я этот vault не вижу и не контролирую, это её база»**. Vault перенесён
в его личный локальный Obsidian под Claude Code — EDITH к нему больше не обращается, скиллы
`vault-pr-write`/`obsidian` отключены, MCP-серверы убраны из конфига. Знания о Михаиле
остаются в обычной встроенной памяти Hermes (не связана с vault, не пострадала).

### 2026-08-14 — эпизод самовольного планирования
EDITH сама выбрала фокусом дня Python ООП и переставила остальные дедлайны, никого не
спросив. Михаилу это было «нахуй не надо» в тот день — он потерял контроль над своими же
сроками без предупреждения. Зафиксировано в SOUL.md как жёсткое правило: никогда не вызывать
`reschedule-tasks` по своей инициативе, только по явной просьбе; предлагать фокус как вопрос,
не как решение; молчание — не согласие.

### 2026-08-25 — переезд в Петербург, часовой пояс
`timezone` в конфиге сменён `Asia/Krasnoyarsk` → `Europe/Moscow`. **Смены ключа оказалось
недостаточно** — см. раздел 6 («Таймзона в cron» — главный найденный баг этого периода).

### 2026-08-28…09-01 — учёт трат: три итерации подряд
Самая длинная цепочка решений в проекте — MacroDroid-пуши → конфликт VPN → Caddy → баги
MacroDroid → успех → тупик с T-Bank → пивот на еженедельные выписки. Полностью в разделе 5.2.

### 2026-09-01 — веб-интерфейс: деньги/почта на главном экране + редизайн
См. раздел 5.8.

### 2026-09-07 — служебные модели: luna вместо mini
Отдельной сессией (не в этом разговоре) `auxiliary.*` переведены с `gpt-5.4-mini` на
`gpt-5.6-luna` + явный `reasoning_effort: minimal` — luna подешевела на 80% на OpenRouter и
стала дешевле mini по всем тарифам, но без явного минимума reasoning-токены reasoning-модели
съели бы всю экономию. Основной диалог получил `agent.reasoning_effort: high` (не max —
платить по полной цене за «который час» бессмысленно).

## 3. Технологический стек

| Слой | Решение | Почему |
|---|---|---|
| Ядро агентов | **Hermes Agent** (NousResearch), сейчас ≥0.20 | Готовые профили, память, cron, MCP, гейтвеи мессенджеров, плагинная система с хуками — вывод из провала v1: не писать инфраструктуру агентов самому |

| Запасная модель (429/перегруз) | `openai/gpt-5.4-mini` | Провайдер иногда отвечает rate-limit — без фолбэка ошибка шла прямо в чат Михаилу |
| Сервер | Contabo EU, Ubuntu 24.04 | **OpenRouter блокирует российские IP (403)** — сервер обязан быть вне РФ. Ру-реселлеры проверялись и отпали (сломанный стриминг у одного, нестандартное расположение ключа у другого). | Голос (STT) | Groq `whisper-large-v3-turbo`, бесплатный тариф без карты | Лучше распознаёт русский, чем локальный `base`, не грузит CPU/RAM сервера |
| Задачи | Todoist через официальный MCP (`@doist/todoist-mcp`) | Единственный источник правды по задачам — не вести параллельный список в памяти |
| Календарь/таблицы | Google Calendar + Sheets через bundled-скилл `productivity/google-workspace` | OAuth, `--services calendar,sheets` |

## 4. Личность (`SOUL.md`) — как EDITH разговаривает

Ключевая идея: не бот, а «толковая секретарша» — компетентная своя, знает контекст, может
сказать «это хуйня, давай иначе», всегда на его стороне. Никакого корпоративного тона.

Правила, установленные прямыми цитатами Михаила:
- **Отзывается сразу, до работы** — короткая реплика («Секунду, гляну Todoist») перед
  вызовом инструментов, не молчит, пока копается.
- **Мат — часть нормальной речи**, естественно, не через слово, никогда не в его адрес обидно.
- **Своё мнение — один раз и прямо, не продавливает.** Решил иначе — принимает, не
  возвращается по третьему кругу.
- **Формат — структура, а не простыня.** Короткие абзацы, списки — читает с телефона на ходу.
- **Доуточняет одним точным вопросом**, если запрос двусмысленный, без допроса из трёх
  уточнений там, где всё понятно.
- **Не выдумывает и не отчитывается об успехе, которого не было** — уже случалось, что она
  сказала «настройка записана», хотя запись была отклонена; это дороже любой ошибки, потому
  что после него нельзя верить ничему.

**Главный приоритет — наставник по самообучению**, выше календаря и денег. Михаил сам сказал:
«поддержать в учёбе и быть наставником по самообучению» — если бы EDITH делала одну вещь
идеально, то эту. Граница: не решает и не учится ЗА него — держит систему на плаву, когда не
хватает воли. Правила из инцидента 2026-08-14 (см. раздел 2) — не переставлять дедлайны
самовольно.

**Порядок приоритетов Михаила словами:** деньги, учёба, дисциплина, переезд и адаптация,
люди и инфа о них, маркетплейс (с сентября), здоровье.

**Проактивность разрешена везде, кроме денежных решений и подписания чего-либо** — там
сначала явное «да».

## 5. Возможности — полный реестр

### 5.1 Календарь и задачи
Google Calendar (смотреть/ставить/двигать, создание-удаление не бесшумно) + Todoist
(единственный источник правды, 9 инструментов из ~45 официального MCP-сервера — остальные
отфильтрованы, чтобы не платить токенами за неиспользуемые схемы на каждом ходу). Перенос
срока — только `reschedule-tasks`, не `update-tasks` (иначе ломается повторяемость).

⚠️ Правило-шрам: **никогда не фильтровать задачи по «назначено мне»** — аккаунт личный, задачи
без назначения, такой фильтр однажды дал пустой список и EDITH соврала «задач нет», хотя их
было полно.

Утренняя сводка (`MORNING.md`, cron 08:00 по времени Михаила) + вечерняя сверка (`EVENING.md`)
— не отчёт и не допрос, разговор про прошедший день. Если сказать нечего — `[SILENT]`, Hermes
подавляет доставку (сводка ради сводки обесценивает канал).

### 5.2 Деньги — три итерации подряд

**Таблица.** Google-таблица, 7 листов, структура собрана заранее по 12 уточняющим вопросам
(2026-07-30) — переделывать структуру задним числом, когда там уже есть данные, дороже, чем
спроектировать сразу:
1. **Операции** — Дата/Тип/Категория/Сумма/Комментарий/Источник дохода.
2. **Категории** — справочник для выпадающих списков, EDITH дописывает новую при необходимости.
3. **Регулярные платежи** — прогноз и напоминания, логирование факта списания только после
   подтверждения.
4. **Цели** — накопления с прогрессом (первая цель: переезд в Петербург).
5. **Бюджеты/Лимиты** — лимиты по категориям (см. ниже, два родственных, но не идентичных
   механизма — исходная спека предполагала формулы SUMIFS на листе «Бюджеты»; сторож лимитов
   2026-08-31 завёл отдельный лист «Лимиты» с ручным заполнением день/неделя/месяц).
6. **Долги** — Мне должны / Я должен, отдельно от обычных операций.
7. **Сводка** — дашборд с круговой диаграммой расходов и линейным графиком баланса.

**Итерация A: автозахват через MacroDroid-пуши (2026-08-28, позже деприоритизирован).**
```
телефон — MacroDroid ловит уведомление банка
  → HTTPS POST → Caddy (публичный) → reverse proxy 127.0.0.1
  → finance_webhook.py — разбор регулярками, БЕЗ LLM
  → строка в лист «Операции»
```
- **Почему MacroDroid, а не своё приложение:** чтение чужих уведомлений — это
  `NotificationListenerService`, полноценное приложение с подписью/сайдлоадом/поддержкой;
  MacroDroid делает то же из коробки за 10 минут.
- **Почему регулярки, а не LLM:** сотни трат в месяц, вызов модели на каждую съедает всю
  экономию идеи. EDITH разбирает неизвестных продавцов пачкой раз в неделю.
- **Почему публичный Caddy, а не Tailscale (пивот 2026-08-28):** изначально вебхук жил только
  в tailnet. Но Android разрешает только **один** активный VPN разом — Михаилу почти
  постоянно нужен обычный VPN для других приложений, и при его включении Tailscale отваливался,
  MacroDroid молча терял связь с вебхуком. Рассмотрены и отклонены: Tailscale exit-node (гонял
  бы весь трафик телефона, включая банковские приложения, через Германию — риск гео-блока
  банка), split tunneling (решает другую задачу — исключение приложения из ОДНОГО тоннеля, не
  сосуществование двух VPN), свой MTProto-прокси для Telegram (решил бы только Telegram, а VPN
  нужен и другим приложениям). Итог — обычный публичный HTTPS через Caddy + sslip.io
  (`169-58-63-99.sslip.io`, бесплатный поддомен без регистрации), риск принят осознанно: секрет
  32 байта, Caddy пропускает ровно `/notification` и `/health`, у вебхука доступ только к
  одной таблице (в отличие от веб-чата EDITH, который остался Tailscale-only принципиально).
- **Живой баг Caddy:** `listen tcp :443: bind: address already in use` — `tailscale serve` уже
  держал 443 на tailnet-интерфейсе под веб-UI. Исправлено явным `bind <публичный IP>` в
  Caddyfile.
- **Живые баги MacroDroid (несколько раундов, все на реальном устройстве, не по документации):**
  «HTTP Request» находится не в категории «Connectivity», а в «Web Interactions» (только через
  поиск); generic-кнопка `...` в полях показывает список системных Android-настроек, а не
  переменные уведомления; стray-переменная после закрывающей `}` в теле JSON ломала запрос в
  HTTP 400 без единой строки в логе (raw-лог пишется только после успешного парсинга JSON) —
  **корневой баг** оказался ещё глубже: настроенный триггер был **«Popup Message»**, а не
  «Notification Received» — совсем другое событие, из-за чего вообще ни одно реальное
  уведомление банка не долетало с самого начала настройки.
- **Данные форматов банков, найденные вживую:** Сбербанк кладёт сумму/направление в `title` с
  emoji-маркером (➕/➖), а не в `text`; Альфа-Банк формулирует входящий перевод как «Перевод на
  сумму… из… от…», что совпадало с маркерами расхода — реальный баг **неправильной
  классификации** (записалось бы как трата, а не доход), исправлено отдельным регэкспом
  для входящих переводов.

**Тупик: T-Bank так и не поймали.** Реальные транзакционные пуши T-Bank не долетали до лога
даже с полностью снятым фильтром по приложениям (`Any Application` в MacroDroid) — то есть
дело не в настройке триггера, а где-то на уровне телефона/прошивки (Samsung — вероятно
Device Care усыпил/ограничил процесс, аналогично истории с самим Tailscale на этом же
телефоне, см. раздел 6). Разбираться дальше признано дороже цены задачи.

**Итерация B (текущая, с 2026-09-01): еженедельный ручной разбор выписок.**
Раз в неделю EDITH сама просит выписки (крон), Михаил присылает файлы (T-Bank — авто раз в
месяц по умолчанию; Альфа — бесплатная авто-рассылка по расписанию в Альфа-Онлайн; Сбербанк —
либо платная услуга, либо ручная выгрузка) прямо в Telegram-чат, EDITH (уже умеет читать
Excel/CSV без плясок, подтверждено вживую) дозаписывает операции с дедупом по дате+сумме+
получателю и даёт разбор — что потрачено зря, где вышло сэкономить, с опорой на «Лимиты» и
категории. Учёт ведётся с 1 сентября 2026 — старые тестовые/вебхучные строки удалены, история
до этой даты в анализ не идёт. MacroDroid/Caddy/вебхук не удалены, оставлены неактивной
инфраструктурой на случай возврата к реальному времени.

**Сторож лимитов (`budget_watchdog.py`, с 2026-08-31), тот же паттерн ноль-LLM.**
Лист «Лимиты» (Категория/Лимит-день/Лимит-неделя/Лимит-месяц) заводится сторожем сам, но
**заполняет цифры только Михаил** — сознательное решение: предлагать лимиты по истории трат
рано, легко закрепить уже сложившееся неаккуратное поведение вместо того, чтобы его
поправить. Два порога — «приближается» (⩾90%) и «превышено» (⩾100%), каждый ровно одно
сообщение за период (день/неделя/месяц, ISO-ключ, сам сбрасывается на границе). Все периоды
считаются в `Europe/Moscow` явно — не пояс сервера (CEST) и не профильный пояс EDITH. Заодно
починена смежная неточность в `finance_webhook.py`: дата операции писалась через
`dt.date.today()` (пояс сервера), могла попасть не в тот календарный день на границе полуночи.

### 5.3 Расписание Политеха → отдельный Google-календарь
`politeh_schedule.py`, тот же ноль-LLM паттерн, тянет с открытого JSON API `ruz.spbstu.ru`
(надёжнее браузера — не ломается от вёрстки). Решения:
- Отдельный календарь «Политех — расписание», не primary — синхронизация **удаляет**
  пропавшие события, ошибка матчинга на основном календаре снесла бы настоящие встречи.
- Часовой пояс `Europe/Moscow` задан явно в коде, не берётся из системы/профиля.
- Пустой ответ ruz (каникулы или сбой сайта — выглядят одинаково) = ничего не трогаем, не
  стираем расписание.
- Подгруппы фильтруются **по предметам явно**, без умолчания «на всё» — нумерация подгрупп
  независима у разных предметов (физика делится как «п/г 1/2», иностранный — как «п/г 01» по
  уровню); одно поле «моя подгруппа = 1» на всё расписание однажды тихо съело все занятия
  английского.
- Окно `weeks_ahead` увеличено 2→5 (по прямой просьбе Михаила — «мало окна, 3 недели, а не
  месяц»), это была не логическая, а количественная правка.
- Крон — воскресенье 20:00 (расписание «плавает», вечер воскресенья ловит новую неделю целиком).

### 5.4 Голос
Автотранскрипция голосовых Telegram встроена в гейтвей (звать инструмент не нужно). Groq
`whisper-large-v3-turbo`, бесплатно. Эхо сырой расшифровки в чат отключено
(`stt_echo_transcripts: false`) — EDITH и так пересказывает суть в ответе. У Groq в этой
версии Hermes нет параметра языка — распознавание по автоопределению модели.

### 5.5 Ресёрч (скилл `research`) — пайплайн с проверяемыми источниками
Декомпозиция вопроса на 2–6 подзапросов → параллельные сабагенты через `delegate_task`,
каждый читает **полные страницы**, не сниппеты → сведение через `scripts/sources.py` (дедуп,
вес источника, сквозная нумерация `[n]`, конфликты не прячутся, показываются обе версии с
датами) → ответ с источниками.

⚠️ **Скиллы в Hermes необязательны к исполнению** — в системный промпт попадает только
компактный индекс, полную инструкцию модель должна сама дочитать через `skill_view`. На
первом живом прогоне (сравнение комиссий Ozon/WB) EDITH скилл **не открыла**, сделала один
общий `delegate_task` и выдала гладкий отчёт без единого `[n]` и с диапазонами вместо чисел —
убедительно и непроверяемо, ровно то, что скилл должен был предотвращать. Лечение — жёсткое
правило в `SOUL.md` (он в системном промпте всегда, в отличие от скилла): для любого вопроса
с внешними фактами обязательно открыть `research`, плюс явный запрет на три способа срезать
угол (ответ по памяти, одиночный `delegate_task`, ответ без `[n]`). Проверено повторно —
заработало.

### 5.6 Delegation — узкая экспертиза без отдельных ботов
`delegate_task` (anonymous fork/join сабагенты) — право фрилансера, матан/линал/ML/алгоритмы,
состояние проектов. Не отдельные боты — Михаил видит один голос EDITH.

### 5.7 Guest Bridge — ответ по @упоминанию из любого чата
Telegram Guest Bots (Bot API 10.0) не поддержаны нативно в Hermes (issue открыт, «no
urgency») — свой мост (`guest_bridge.py`) в обход. Ключевое архитектурное решение: **бот-
двойник**, не тот же токен, что у основного гейтвея — Telegram разрешает только одно активное
`getUpdates`-подключение на токен, общий токен уронил бы основного бота через retry-логику.
Отдельный бот с тем же именем/аватаркой, свой токен, свой слот. Отвечает та же EDITH через
`/v1/chat/completions` (`api_server`, `127.0.0.1:8642`). Allowlist (`TELEGRAM_ALLOWED_USERS`)
реализован в мосте заново — `guest_message` идёт от **любого** пользователя в обход
стандартной проверки Hermes. Ограничение: один ответ на упоминание, без памяти о переписке
группы — так спроектирована privacy-модель guest-ботов в самом Telegram.

### 5.8 Веб-интерфейс EDITH — свой, вместо Telegram и вместо дашборда Hermes
Причина: «нахуй этот дашборд [встроенный Hermes], он мне очень не нравится, нам нужен свой» +
Telegram как чужой мессенджер не даёт своего форматирования и места рядом с чатом.

```
браузер (телефон/комп, оба в tailnet)
  → server.py — отдаёт страницу, хранит историю (своя SQLite), стримит ответ
  → gateway EDITH, /v1/chat/completions на 127.0.0.1:8642
```

Решения: прокси, а не прямой запрос из браузера в gateway (ключ не должен оказаться в JS на
телефоне); история — последние 12 сообщений в gateway, не вся (экономия токенов); стриминг с
откатом на обычный ответ; ответ дочитывается даже при закрытой вкладке (деньги уже
потрачены); свой минимальный markdown-рендер без библиотек (страница должна работать офлайн,
плюс экранирование ПЕРВЫМ шагом — ответ EDITH может содержать чужой HTML со страниц, которые
она читала браузером); токен в localStorage + cookie на год (вход один раз за устройство);
только tailnet — полный доступ к EDITH (почта/задачи/деньги/календарь), наружу нельзя.

**Главный экран вместо пустого чата** — приветствие (по часам ТЕЛЕФОНА, не сервера/профиля,
без вызова модели), ближайшие события/задачи из кэша (открывается мгновенно, обновляется в
фоне — «медленность и скука... чем больше действий мне приходится делать, тем меньше у меня
желания делать что-то»). Голосовой ввод — та же Groq-транскрипция, что в Telegram. Статус во
время ответа («смотрю задачи · 12с») — реальный вызов инструмента + секундомер, против
ощущения «тупо хуйнёй страдает и тратит токены».

⚠️ **Микрофон и офлайн-кэш работают только по HTTPS** — `navigator.mediaDevices` физически не
существует на `http://<tailnet-ip>`. Решено штатным `tailscale serve --bg --https=443` —
бесплатный сертификат на tailnet-домен (`https://<машина>.<tailnet>.ts.net`).

**Живой случай (2026-09-01): `ERR_TUNNEL_CONNECTION_FAILED` с телефона.** Диагностика по
`tailscale status` показала: телефон (`s25-ultra`) значился `offline, last seen 4d ago` —
сервер и сам `tailscale serve` были в полном порядке. Причина — Samsung Device Care усыпил
фоновый процесс Tailscale на телефоне (та же категория проблемы, что и необъяснённый провал
захвата уведомлений T-Bank, раздел 5.2). Решение — вручную переподключить + исключить
Tailscale из ограничений батареи на телефоне.

**Деньги и почта на главном экране (2026-09-01).** Две плитки с тоном по статусу лимитов
(в порядке/близко/превышено — цвет несёт смысл, не украшение) и числом непрочитанных писем.
⚠️ Обеим нужен более широкий scope у Google-токена, чем есть — токен веб-интерфейса заводился
сознательно узким (`--services calendar`), Sheets/Gmail не входили; обе функции реализованы
отказоустойчиво — при нехватке прав молча прячут блок вместо ошибки, тем же диалоговым
способом чинится (попросить EDITH расширить OAuth), каким заводился сам Calendar изначально.

**Редизайн 2026-09-01** — по референсу открытого репозитория `marvkr/better-design` (набор
токенов/компонентов 31 продуктового дизайн-системы для AI-агентов, не библиотека под наш
стек — портированы конкретные приёмы вручную в чистый CSS): глубокая сине-фиолетовая палитра
на `oklch()` вместо плоского серо-чёрного (Linear-стиль), многослойные тени на карточках
(внешняя мягкая + тонкий контур + верхний инсет-блик), тень-кольцо + press-feedback на
кнопках, плашки-«пилюли» для статуса лимитов вместо простого цветного текста, единая шкала
радиусов и таймингов переходов, focus-visible + клавиатурная активация на карточках (были
недоступны с клавиатуры).

## 6. Ключевые инфраструктурные решения и подводные камни Hermes (кросс-проектные)

| Проблема / решение | Суть |
|---|---|
| **Геоблокировка → сервер вне РФ** | OpenRouter отдаёт 403 российским IP — сервер Contabo EU обязателен |
| **Cloud.ru отклонён** | Та же модель там в 5-10 раз дороже в рублёвом эквиваленте |
| **Таймзона в cron — главный найденный баг проекта** | У каждой cron-задачи хранится АБСОЛЮТНОЕ время следующего запуска, посчитанное на момент СОЗДАНИЯ в старом поясе. Правка ключа `timezone:` в конфиге НЕ пересчитывает уже существующие задачи. После переезда в Питер это привело к тому, что утренняя/вечерняя сводка и синхронизация расписания стреляли на 4 часа раньше по факту (сводка приходила в 4 утра) — выглядело как «кроны вообще не присылает». Лечится только пересозданием каждой cron-задачи по времени суток (`cron remove` + `cron create` заново, НЕ `cron delete` — неверное имя подкоманды) |
| **`cron create "at HH:MM"` не работает** | Парсер понимает `30m`, `every 2h`, cron-выражения — не «at HH:MM». Использовать `"0 8 * * *"` |
| **Cron не срабатывает при живом `next_run_at`** | Тикер живёт внутри gateway, не отдельным процессом — держать gateway запущенным |
| **Служебная обёртка `Cronjob Response: ...` в Telegram** | Отключается `cron.wrap_response: false` |
| **`disabled_toolsets` в профиле заменяет, не дополняет** | Машинный список (36 позиций) полностью перезаписывается профильным — если перечислить только 7, остальные 29 молча включатся (так однажды ожил `kanban`) |
| **`platform_toolsets` с конкретным списком требует ЯВНО указать `delegation`** | Без него нет `delegate_task` — а на нём вся внутренняя специализация EDITH и весь скилл `research`. Сабагенты наследуют инструменты родителя минус блок-лист, поэтому `web` в списке нужен и им |
| **YAML 1.1 булевы ловушки** | `off` без кавычек читается как `False`, а код делает `str(v).lower() if v else "on"` — без кавычек эффект получается ПРОТИВОПОЛОЖНЫЙ задуманному, молча (`display.memory_notifications`, `browser.backend`) |
| **Дорогой контекст — 116.5M из 120.5M токенов были перечитыванием кэша** | Порог сжатия по умолчанию — доля от огромного окна модели (у Luna 400K-1M), срабатывает раз в месяц. Одна незакрытая Telegram-сессия (646 сообщений) съела 78% всех трат за период. Исправлено: `compression.threshold_tokens: 60000` (абсолютный порог), `proactive_prune_tokens` (бесплатная детерминированная чистка вывода инструментов без LLM), `idle_compact_after_seconds: 3600` |
| **94 установленных скилла, реально гружено 9 за 30 дней** | Риск не в цене индекса (дёшево, кэшируется), а в том что `skill_view` грузит `SKILL.md` ЦЕЛИКОМ в диалог до конца сессии — среди неиспользуемых были файлы по 24-34 KB. Отключены плоские имена всех неиспользуемых |
| **`.env` не перечитывается на лету** | Переменные читаются при старте процесса — нужен полный рестарт агента, не просто новый диалог |
| **`office-gate` v2 → v3 (для истории, сейчас неактуально — офис снесён)** | v2: семь независимых да/нет-решений без общего арбитра дали худший исход при сбое классификатора — отвечали ВСЕ семь агентов разом. v3: сверху вниз, первое совпадение выигрывает, модель зовётся только на последнем шаге (арбитраж атомарной гонкой `INSERT OR IGNORE` за право решить) |
| **Секрет один раз попал в контекст модели** | Владелец вставил GitHub-токен прямо в чат агенту — практика исправлена, токен стоило ротировать |
| **Единая точка отказа — один VPS** | Бэкапов конфигов вне git на момент фиксации не было |

## 7. Известные ограничения, риски и отложенное (на 2026-09-08)

- **T-Bank не ловится в реальном времени** — тупик, дороже цены задачи, закрыт пивотом на
  еженедельные выписки (раздел 5.2). Не исключено, что причина так и не найдена (Samsung
  battery/Device Care — рабочая гипотеза, не подтверждённая).
- **Маркетплейс WB/Ozon** — главный бизнес-приоритет по роадмапу, старт «~сентябрь» (сейчас
  сентябрь). Гео-доступ уже проверен с боевого сервера — блокировки нет (все домены отвечают
  401 за 0.05-0.12с), ру-прокси не нужен. Не хватает только ключей продавца от Михаила.
  ⚠️ Мёртвый домен для справки: `suppliers-api.wildberries.ru` отключён 30 января 2025, не
  использовать. Ключ WB живёт 180 дней — нужно напоминание на продление.
- **Веб-дашборд — деньги/почта требуют расширения Google OAuth scope**, ещё не подтверждено
  выполненным на 2026-09-08.
- **Выжимка за неделю по разговорам веб-интерфейса + закрепление важного** — история уже в
  SQLite, разбор и пометка ещё не реализованы.
- **Входящие личные сообщения Telegram («secretary mode»)** — бот видит только то, что пишут
  ему напрямую; личные диалоги требуют MTProto/Telethon-клиента от аккаунта Михаила — легально,
  но отдельная работа и вторая точка, где лежит доступ к переписке. Не начато.
- **ВКонтакте — решено не делать.** VK не выдаёт scope `messages` новым приложениям; всё
  рабочее так или иначе нарушает правила VK и грозит баном личного аккаунта.
- **Единая точка отказа — один VPS**, бэкапы конфигов вне git не гарантированы.
- **Секретарский/EDITH-профиль имеет полный shell** — вынужденно (Google Workspace скрипт не
  имеет отдельных тулов, всё идёт через `google_api.py` в терминале). Смягчено
  `approvals.mode: manual`, но технического барьера на команды вне календаря нет.
