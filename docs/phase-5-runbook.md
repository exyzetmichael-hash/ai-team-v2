# Фаза 5 — Runbook: офис (агенты видят друг друга)

> ⚠️ **Это черновик, не готовая инструкция «сделал — работает».** Всё здесь опирается только на документацию и исходники Hermes v0.19.0 (не на живой тест — у меня нет второго агента и группового чата, чтобы это прогнать). Начинай эту фазу **только после того, как секретарь и brain оба пожили какое-то время** и ты понимаешь их характер — калибровка гейта имеет смысл только на реальных сообщениях.

**Цель:** агенты передают друг другу работу через Kanban (без куратора, каждый решает сам) и в общем Telegram-чате отвечает тот, кому тема ближе — без того, чтобы каждое сообщение поднимало всех агентов разом.

Два независимых механизма, можно внедрять по отдельности:
- **Kanban** — передача задач между агентами (готовая фича Hermes, не наш код).
- **office-gate** — дешёвый гейт для группового чата (наш черновой плагин).

---

## Часть 1 — Kanban (передача задач)

Это встроенная функция Hermes, не наш код — просто её ещё не включали (`kanban` был у секретаря и brain намеренно в `disabled_toolsets` с самого начала, с пометкой «включим на этапе офиса»).

### 1.1 Включить kanban-тулсет
В `~/.hermes/profiles/secretary/config.yaml` и `~/.hermes/profiles/brain/config.yaml` убери `kanban` из списка `agent.disabled_toolsets` (просто удали строку `- kanban`).

### 1.2 Описать роли профилей
Диспетчер Kanban раздаёт задачи по профилям на основе их описания:
```bash
hermes profile describe secretary --auto
hermes profile describe brain --auto
```
`--auto` — Hermes сам сгенерирует описание по SOUL.md и установленным скиллам. Проверь, что описания вменяемые:
```bash
hermes profile describe secretary
hermes profile describe brain
```

### 1.3 Проверить, что диспетчер крутится в gateway
По умолчанию должно быть уже включено (`kanban.dispatch_in_gateway: true` — дефолт), но убедись:
```bash
grep -A2 "^kanban:" ~/.hermes/config.yaml
```
Если секции нет — она и не нужна, дефолт уже верный.

### 1.4 Тест — дать задачу через доску
```bash
hermes kanban create "Узнать у секретаря, сколько дедлайнов на этой неделе" --assignee secretary
hermes kanban list
```
Подожди ~60 секунд (тик диспетчера) или подтолкни явно:
```bash
hermes kanban list   # смотри, сменился ли статус todo -> ready -> running -> done
```
Секретарь должен сам подхватить задачу и выполнить её без твоего участия в диалоге.

**Доска видна в вебе** — как только сделаем Фазу 6 (нативный дашборд), там будет отдельная вкладка Kanban с визуальными карточками (drag-and-drop). Пока без дашборда работай через CLI/`  /kanban` в чате.

## Часть 2 — office-gate (групповой Telegram-чат)

### 2.1 Завести общий Telegram-чат
Создай группу в Telegram, добавь туда обоих ботов (`@myaisecretary1_bot` и бота brain, если у него отдельный) **и себя**. Узнай `chat_id` группы (проще всего — написать что-то в группу и посмотреть в логах `agent.log`/`gateway`, какой `chat_id` пришёл).

### 2.2 Разрешить группу в allowlist каждого профиля
```bash
# в .env каждого профиля (secretary, brain):
echo 'TELEGRAM_GROUP_ALLOWED_CHATS=<ID группы>' >> ~/.hermes/profiles/secretary/.env
echo 'TELEGRAM_GROUP_ALLOWED_CHATS=<ID группы>' >> ~/.hermes/profiles/brain/.env
```
(Точное имя переменной проверь в `hermes -p secretary gateway setup` — там же можно добавить группу через мастер, это надёжнее ручного редактирования `.env`.)

### 2.3 Поставить плагин office-gate на КАЖДЫЙ профиль, что участвует в офисе
```bash
mkdir -p ~/.hermes/profiles/secretary/plugins ~/.hermes/profiles/brain/plugins
cp -r ~/ai-team-v2/plugins/office-gate ~/.hermes/profiles/secretary/plugins/
cp -r ~/ai-team-v2/plugins/office-gate ~/.hermes/profiles/brain/plugins/
hermes -p secretary plugins enable office-gate
hermes -p brain plugins enable office-gate
```
Перезапусти gateway обоих профилей, чтобы плагин подхватился — используй сам `hermes`, а не руками `systemctl`: Hermes по умолчанию ставит **user-scope** systemd-юнит (`hermes-gateway-<профиль>`), а не системный, так что `sudo systemctl restart` может целить не в тот scope или не найти юнит вовсе. `gateway restart` сам разбирается, user это или system (флаг `--system`, если ты явно ставил как системный сервис):
```bash
hermes -p secretary gateway restart
hermes -p brain gateway restart   # если у brain уже настроен gateway-сервис
```

### 2.4 План калибровки — вот тут начинается реальная работа
Это **не** «поставил и работает», это отправная точка для настройки на живых сообщениях. Проверяй по очереди:

1. **Напиши в группу что-то явно про дедлайн** («напомните мне про сдачу курсовой») — должен ответить только secretary, brain должен промолчать (skip).
2. **Напиши явно про заметки/vault** («что у нас в vault про X») — должен ответить только brain.
3. **Напиши что-то нейтральное, не по теме ни одного из них** («привет, как дела») — оба, скорее всего, промолчат (или один из них ответит на светскую реплику — это нормально, гейт не обязан быть идеальным).
4. **Обратись по имени явно** («секретарь, …») — должен ответить именно он, минуя классификатор (это в коде уже так, проверь, что реально работает).
5. **Проверь, что НИ ОДИН агент не потерялся навсегда** — если оба молчат на сообщение, где явно должен ответить хотя бы один, это главный сигнал, что порог классификации слишком строгий или промпт классификатора неудачный — пиши мне, поправим формулировку в `_classify()`.

Если после недели реального использования гейт систематически ошибается — это ожидаемо, не поломка. Пришли мне 5-10 примеров (сообщение → кто ответил / кто должен был) и я перепишу промпт классификатора под них.

### 2.5 Известные слабые места черновика (честно, заранее)
- Классификатор видит только **первый абзац SOUL.md** — если роль сформулирована нечётко в первом абзаце, гейт будет ошибаться. Можно вручную поправить `_load_role_summary()` под более точную формулировку.
- Нет защиты от того, что **оба агента ответят одновременно** на пограничное сообщение — в брифе это было допустимо («высказывается каждый, кто относится к задаче»), но если будет раздражать — добавим правило «отвечает только тот, у кого выше уверенность классификатора» (сейчас классификатор возвращает только да/нет, не число — это первое, что стоит доработать, если понадобится).
- Упоминание по имени — грубая строка `profile.lower() in text.lower()`, не понимает склонений («секретарю», «секретарём»). Не проверял на реальном русском тексте.

## Критерии готовности фазы 5
- [ ] Задача, поставленная на Kanban-доску, подхватывается назначенным профилем без ручного вмешательства.
- [ ] В групповом чате хотя бы в половине случаев отвечает релевантный агент, а не оба/никто.
- [ ] Явное упоминание по имени работает как гарантированный способ достучаться до конкретного агента.
