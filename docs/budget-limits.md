# Лимиты по деньгам — сторож без LLM

Причина существования — прямая цитата Михаила (2026-08-24): деньги «пока
вообще нету в моей жизни, и это очень плохо — уже переехал, начал жить
самостоятельно, но учёта трат нет и очень много лишних покупок». Видеть
цифры в таблице постфактум не помогает — решение принимается **до**
покупки. Сторож ловит момент, когда категория пробивает порог, и
предупреждает сразу.

Файл: [`scripts/budget_watchdog.py`](../profiles/edith/scripts/budget_watchdog.py).
Тот же паттерн, что сторож почты и синхронизация расписания:
**ни одного вызова LLM**, `cron --script --no-agent`, пустой stdout —
тишина и ноль стоимости.

## Два листа

**«Операции»** — уже существующий журнал трат, пишет `finance_webhook.py`
при каждой распознанной покупке (см. [`finance-capture.md`](finance-capture.md)).

**«Лимиты»** — заводится сторожем сам при первом запуске, если его ещё нет
(только заголовки). Заполняет **Михаил сам** — это осознанное решение:
предлагать лимиты автоматически по истории трат за неделю-две рано, легко
подстроить бюджет под уже сложившееся неаккуратное поведение вместо того,
чтобы его поправить.

| Категория | Лимит/день | Лимит/неделя | Лимит/месяц |
|---|---|---|---|
| Еда | 1000 | | 25000 |
| Развлечения | | 3000 | |

Пустая ячейка = период не проверяется для этой категории. Можно задать
только один период на категорию, можно все три — независимо друг от друга.
Категории — те же названия, что в листе «Категории» основной таблицы.

## Два порога, каждый — одно предупреждение за период

**«Приближается» (⩾90%)** — ещё можно притормозить до перерасхода.
**«Превышено» (⩾100%)** — по факту.

Каждый порог по каждой категории и периоду — **ровно одно** сообщение,
пока период не сменится. Без этого дедупа сторож в режиме «весь день
красная категория» слал бы одно и то же сообщение каждый час до полуночи.
Состояние — `budget_watchdog_state.json`, ключ на комбинацию
категория+период+уровень, сбрасывается сам при смене дня/недели/месяца.

## Пояс

Все границы периодов — **Europe/Moscow**, не пояс сервера (CEST) и не
профильный пояс EDITH. Деньги Михаила живут по его реальному календарю в
Питере. Тот же принцип, что в `politeh_schedule.py`.

⚠️ Заодно поймана и починена смежная неточность: `finance_webhook.py`
писал дату операции через `dt.date.today()` — это пояс **сервера**, не
Москвы. На границе полуночи (между 00:00 Москвы и 01:00 CEST) трата
попадала бы не в тот календарный день, и сторож лимитов считал бы день
неверно. Теперь дата пишется явно по `Europe/Moscow` (`MONEY_TZ` в обоих
файлах).

## Настройка

Ничего заводить не нужно отдельно — использует тот же `finance_webhook.json`
(поле `spreadsheet_id`), что и приём трат. Достаточно:

```bash
HERMES_HOME=~/.hermes/profiles/edith python3 budget_watchdog.py
```

Первый прогон создаст лист «Лимиты», если его нет, и выйдет молча (лимитов
ещё не вписано — проверять нечего). Впиши цифры в таблицу, дальше сторож
подхватит их сам на следующем прогоне.

## Крон

```bash
hermes -p edith cron create "every hour" \
  --script budget_watchdog.py --no-agent \
  --name "Сторож лимитов" --deliver telegram
```

Раз в час достаточно — решение о покупке не становится быстрее от более
частой проверки, а лишний трафик Sheets API (квота, не деньги) ни к чему.
