# Свой дашборд EDITH — Vault + граф (кусок 1 из плана)

Личный дашборд строится не с нуля, а поверх плагин-системы `hermes dashboard`
(`~/.hermes/plugins/<name>/dashboard/` — темы, вкладки, backend-роуты на
FastAPI, без форка и без npm-сборки). Причины решения и весь план по
кускам — история проекта: чат, просмотр сессий и авторизация уже есть
в самом Hermes, переизобретать их не нужно.

Собрано и запланировано:

| Кусок | Статус |
|---|---|
| Vault: просмотр заметок + граф связей (read-only) | ✅ этот файл |
| Публичный доступ без VPN (Nous OAuth) | 📋 следующий шаг, отдельно от вкладки |
| Живой монитор сабагентов/задач в реальном времени | 📋 дальше по плану |
| Личный блокнотик | Уже покрыт — пишется как обычные заметки в vault, EDITH видит их в памяти |

## Что делает вкладка Vault

Новая вкладка в дашборде (`/vault`) — двухпанельный просмотр: дерево папок
и заметок слева, рендер выбранной заметки справа (свой минимальный
markdown-рендер: заголовки, списки, код, ссылки, `[[wikilink]]` —
кликабельные, ведут на связанную заметку). Второй режим — «Граф»: те же
заметки и связи по `[[wikilink]]`, разложенные force-directed layout'ом
(Fruchterman-Reingold, свой расчёт в JS, без d3), клик по узлу открывает
заметку.

**Read-only принципиально** — пишет в vault только сама EDITH через свой
`vault-pr-write` скилл (PR-дисциплина, git-история, ревью). Дашборд не
заводит второй, неконтролируемый путь записи в тот же репозиторий.

Файлы: [`plugins/edith-vault/dashboard/`](../plugins/edith-vault/dashboard/)
— `manifest.json` (регистрация вкладки), `plugin_api.py` (backend: дерево,
содержимое заметки, граф), `dist/index.js` (вся вкладка целиком, plain
IIFE), `dist/style.css`.

## Откуда берётся путь к vault

Порядок приоритета в `plugin_api.py`:
1. `EDITH_VAULT_PATH` — если задана в окружении процесса дашборда.
2. `OBSIDIAN_VAULT_PATH` из `~/.hermes/profiles/edith/.env` — читается
   напрямую из файла, потому что дашборд — machine-level процесс и не
   обязательно наследует `.env` конкретного профиля.
3. `~/vault` как последний резервный вариант.

Для обычного деплоя ничего дополнительно настраивать не нужно — путь
подхватится из `.env` профиля EDITH автоматически.

## Деплой

⚠️ **История (2026-08-01):** на сервере дашборд уже был поднят вручную
29 июля — фоновый процесс без systemd, `hermes dashboard --host
100.91.242.8 --port 9119 --no-open` (Tailscale IP сервера, не
`127.0.0.1` — потому дашборд открывается напрямую с любого устройства в
Tailscale-сети, без SSH-туннеля). Backend-роуты плагинов монтируются
**только при старте процесса** — рескан-эндпоинт их не подхватывает, а
без systemd рестарт означало «найти PID и убить руками». Заведён
нормальный юнит — см. шаги ниже, дальше рестарт всегда через
`systemctl --user restart hermes-dashboard`.

Дашборд должен быть уже установлен (`web` extra — см. `hermes dashboard`
в документации Hermes). Если ещё не поднимался на сервере:

```bash
cd ~/.hermes/hermes-agent && uv pip install -e ".[web,pty]"
```

Сама вкладка + перевод дашборда на systemd:

```bash
cd ~/ai-team-v2 && git pull
mkdir -p ~/.hermes/plugins
cp -r plugins/edith-vault ~/.hermes/plugins/edith-vault

# Старый ручной процесс — найти и остановить (замени PID на актуальный):
ps aux | grep "hermes dashboard"
kill <PID>

# Юнит — один раз:
mkdir -p ~/.config/systemd/user
sed "s#/home/michael#$HOME#g" ops/hermes-dashboard.service.template \
  > ~/.config/systemd/user/hermes-dashboard.service
systemctl --user daemon-reload
systemctl --user enable --now hermes-dashboard
systemctl --user status hermes-dashboard
```

Дальше при любом обновлении плагинов — просто:
```bash
systemctl --user restart hermes-dashboard
```

## Проверка

С самого сервера (или откуда угодно в Tailscale-сети, подставив
Tailscale IP):
```bash
curl -s http://100.91.242.8:9119/api/dashboard/plugins | grep edith-vault
curl -s http://100.91.242.8:9119/api/plugins/edith-vault/tree
```

Второй вызов должен вернуть список путей `.md`-файлов из vault. Открой
`http://100.91.242.8:9119` в браузере на устройстве, подключённом к той
же Tailscale-сети — во вкладках должна появиться **Vault**.

## Известные упрощения v1

- Дубли имён заметок в разных папках: `[[wikilink]]` разрешается в первую
  найденную при обходе — если в vault есть две заметки с одинаковым
  именем в разных папках, связь может указать не туда. Для личного vault
  Михаила такое пока не встречалось, чинить по факту, если понадобится.
- Граф — не «умный» граф Graphify (тот LLM-based, извлекает сущности и
  связи из содержимого, отдельный платный проход) — это прямой,
  бесплатный, мгновенный граф по `[[wikilink]]`, ровно как в самом
  Obsidian. Другой инструмент для другой задачи.
- Layout для больших vault (несколько сотен+ заметок) может подтормаживать
  — расчёт O(n²) на 250 итераций в браузере. Не проблема для текущего
  размера vault, но если он вырастет на порядок — стоит переделать на
  инкрементальный layout или ограничить число итераций.

## Следующий шаг: публичный доступ без VPN

Не часть этого деплоя — отдельное осознанное действие, потому что меняет
профиль риска (дашборд читает/пишет `.env` со всеми ключами). Когда
будешь готов:

```bash
hermes setup            # если ещё не залогинен в Nous Portal
hermes dashboard register
hermes dashboard --host 0.0.0.0 --port 9119 --no-open
```

Дальше — `/login` → «Sign in with Nous Research». Подробности и проверка
gate — в официальной доке Hermes, раздел Web Dashboard → Authentication.
