# Автоматический учёт трат — банковские пуши с телефона в таблицу

Причина существования — прямая цитата Михаила: «щас мне придётся писать
EDITH по каждой мелкой трате, я это дело заброшу очень скоро». Так и
происходит со всеми ручными трекерами. Трата должна попадать в таблицу
без единого действия человека, иначе учёт умрёт через неделю.

```
телефон (Android) — MacroDroid ловит пуш банка
  → HTTPS POST на публичный домен (Caddy)
  → reverse proxy на 127.0.0.1 (finance_webhook.py на сервере)
  → разбор регулярками (БЕЗ LLM, ноль стоимости)
  → строка в лист «Операции» финансовой таблицы
```

Файлы:
[`scripts/finance_webhook.py`](../profiles/edith/scripts/finance_webhook.py),
[`scripts/finance_rules.json`](../profiles/edith/scripts/finance_rules.json),
[`ops/hermes-finance-webhook.service.template`](../ops/hermes-finance-webhook.service.template),
[`ops/Caddyfile.finance-webhook`](../ops/Caddyfile.finance-webhook).
Структура таблицы — [`finance-sheet-spec.md`](finance-sheet-spec.md).

## Почему так, а не иначе

**MacroDroid, а не своё Android-приложение.** Чтение чужих уведомлений —
это `NotificationListenerService`, то есть полноценное приложение: сборка,
подпись, сайдлоад, поддержка при каждом обновлении Android. MacroDroid
делает ровно то же самое из коробки, настраивается за десять минут и не
требует ни строчки кода. Протокол здесь простой (один POST), так что если
однажды упрёмся в ограничения — своё приложение пишется поверх того же
сервиса, серверную часть менять не придётся.

**Публичный HTTPS через Caddy, не Tailscale.** ⚠️ Решение сменилось
2026-08-28. Изначально вебхук жил только в tailnet — та же логика, что у
веб-интерфейса EDITH («Публичный эндпоинт с деньгами надо защищать
всерьёз»). Но выяснилось: Android разрешает только **один** активный VPN
разом, а Михаилу почти постоянно нужен обычный VPN для других приложений —
включаешь его, Tailscale отваливается, MacroDroid молча теряет связь с
вебхуком, траты перестают долетать без единой ошибки на экране.

Разбирали несколько альтернатив, все отклонены:
- **Tailscale exit node** (сервер как выход в интернет для телефона) решал
  бы конфликт VPN, но гонял бы ВЕСЬ трафик телефона через Германию —
  ломает банковские приложения, которые проверяют геолокацию IP.
- **Split tunneling** — это про исключение приложения из тоннеля ОДНОГО
  VPN, не про два VPN разом. Не решает проблему в принципе, это разные
  задачи с похожим названием.
- **Свой MTProto-прокси для Telegram** решал бы только Telegram — у
  Михаила VPN нужен и другим приложениям, значит общего решения не даёт.

Единственный путь, который не зависит от того, какой VPN включён на
телефоне (или выключен вовсе) — сделать вебхук обычным публичным HTTPS-
адресом, как любой другой сайт. Тогда MacroDroid достукивается всегда, тем
же способом, каким сейчас работает любое приложение при любом VPN.

**Риск принят осознанно, не проигнорирован.** Вебхук теперь виден из
интернета. Смягчено тем, что у эндпоинта узкая, конкретная функция:
- секрет — 32 случайных байта, подбором не берётся ни при какой скорости
- даже с утёкшим секретом чужой человек может только вписать фиктивную
  строку в лист «Операции» — не залезть в почту, Todoist, календарь или
  что-либо ещё; у вебхука нет доступа ни к чему, кроме одной таблицы
- Caddy пропускает наружу ровно два пути (`/notification`, `/health`),
  всё остальное — 404 ещё до того, как запрос доходит до самого скрипта

Это не то же самое, что открыть веб-чат EDITH наружу — там был бы полный
доступ ко всему, и тот остаётся Tailscale-only осознанно. Здесь блок-радиус
узкий, и открытость даёт то, ради чего всё затевалось: учёт трат работает
всегда, а не «пока VPN не понадобился для чего-то ещё».

**Регулярки, а не LLM.** Разбор траты должен стоить ноль: трат в месяц
сотни, и вызов модели на каждую съел бы ровно то, ради чего затевалась вся
экономия. Неизвестные продавцы копятся, и EDITH разбирает их пачкой раз в
неделю — один вызов на десяток трат вместо вызова на каждую.

**Сырое пишется всегда и первым.** До любой попытки разбора уведомление
целиком уходит в `finance_raw.jsonl`. Регулярки заведомо неидеальны и
будут дописываться; без сырого лога каждая их правка означала бы
безвозвратно потерянные траты.

## Порядок внедрения — сначала сырьё, потом разбор

⚠️ **Не включай запись в таблицу с первого дня.** Форматы пушей у банков
разные и меняются; регулярки написаны по типовым образцам, а не по твоим
реальным уведомлениям. Мусор в журнале операций чинить дороже, чем
подождать два дня.

**Этап 1 (день-два):** `raw_only: true` в конфиге. Сервис принимает и
складывает уведомления, в таблицу не пишет ничего. Живёшь обычной жизнью,
платишь картой как всегда.

**Этап 2:** смотрим накопленное и правим регулярки под реальные форматы:
```bash
tail -50 ~/.hermes/profiles/edith/finance_raw.jsonl
```
Проверить разбор конкретного текста, ничего не записывая:
```bash
HERMES_HOME=~/.hermes/profiles/edith python3 finance_webhook.py --test-parse "Покупка. Карта *1234. 450 ₽. Пятёрочка. Баланс: 12 345 ₽"
```

**Этап 3:** `raw_only: false`, перезапуск — траты пошли в таблицу.

## Настройка

### 1. Публичный IP и Caddy

Узнать реальный публичный IP сервера (если не помнишь):
```bash
curl -s https://ifconfig.me
```

Поставить Caddy (официальный apt-репозиторий, Ubuntu/Debian):
```bash
sudo apt install -y debian-keyring debian-archive-keyring apt-transport-https curl
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/gpg.key' | sudo gpg --dearmor -o /usr/share/keyrings/caddy-stable-archive-keyring.gpg
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt' | sudo tee /etc/apt/sources.list.d/caddy-stable.list
sudo apt update
sudo apt install -y caddy
```

Открыть порты (Caddy получает сертификат по 80, отдаёт сайт по 443 —
без 80 автопродление сертификата будет молча ломаться раз в несколько
месяцев):
```bash
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
```
⚠️ Если это не сработает так же, как ранее не срабатывал SSH на 22 порту —
блокировка может быть не в `ufw`, а в панели провайдера (Contabo) или
где-то по пути. Раньше эту причину найти снаружи не удалось (см. историю
проекта про диагностику SSH-таймаута) — если `https://<домен>/health`
не откроется после всех шагов ниже, разбираться придётся так же, как в тот
раз: через терминал EDITH изнутри плюс панель провайдера.

Положить конфиг из репозитория (поправь IP в файле на актуальный из шага
выше, если он отличается от `169.58.63.99`):
```bash
sudo cp ~/ai-team-v2/ops/Caddyfile.finance-webhook /etc/caddy/Caddyfile
sudo systemctl reload caddy
```

### 2. Конфиг сервиса

⚠️ `host` теперь **`127.0.0.1`**, не tailnet-адрес — снаружи вебхук
выставляет Caddy, сам сервис слушает только локально.

```bash
python3 - <<'PY'
import json, secrets, pathlib
p = pathlib.Path.home() / ".hermes/profiles/edith/finance_webhook.json"
p.write_text(json.dumps({
    "secret": secrets.token_urlsafe(32),
    "spreadsheet_id": "<id финансовой таблицы из её URL>",
    "host": "127.0.0.1",
    "port": 8765,
    "raw_only": True
}, ensure_ascii=False, indent=2), encoding="utf-8")
p.chmod(0o600)
print("секрет:", json.loads(p.read_text())["secret"])
PY
```
Секрет генерируется на месте и печатается один раз — его вводить в
MacroDroid. В git этот файл не попадает и не должен.

Если конфиг уже существовал (перенос со старой Tailscale-схемы) — просто
поменяй `host` на `127.0.0.1` в существующем файле, секрет и
`spreadsheet_id` менять не нужно, MacroDroid их уже знает.

Правила категорий положить рядом:
```bash
cp ~/ai-team-v2/profiles/edith/scripts/finance_rules.json ~/.hermes/profiles/edith/
```

### 3. Сервис

```bash
cp ~/ai-team-v2/profiles/edith/scripts/finance_webhook.py ~/.hermes/profiles/edith/scripts/
sed 's|/home/michael|'"$HOME"'|g' ~/ai-team-v2/ops/hermes-finance-webhook.service.template \
  > ~/.config/systemd/user/hermes-finance-webhook.service
systemctl --user daemon-reload
systemctl --user enable --now hermes-finance-webhook
systemctl --user status hermes-finance-webhook
```

Если сервис уже был запущен (перенос со старой схемы) — после правки
`finance_webhook.json` достаточно `systemctl --user restart hermes-finance-webhook`.

Проверка (с любого устройства, не обязательно из tailnet — это весь смысл):
```
https://<домен, напр. 169-58-63-99.sslip.io>/health   →   {"ok": true}
```

### 4. MacroDroid на телефоне

⚠️ Развёрнуто и отлажено вживую 2026-08-29 — инструкция ниже описывает
реальный интерфейс, не документацию MacroDroid. Категории пунктов меню
у MacroDroid нестабильны между версиями (в частности, «HTTP Request»
живёт не в «Connectivity», как можно ожидать, а в «Web Interactions» —
не гадай, ищи через иконку 🔍 в шапке экрана).

**Создать макрос:** MacroDroid → **+** → Add Macro.

**Триггер:** Add Trigger → **Applications** → **Notification Received**.
Выбрать приложения своих банков. Не ставить «любое приложение» — иначе
сюда полетит весь шум с телефона. Поле **Text to match** оставить пустым:
весь разбор (сумма, направление, категория) происходит на сервере
регулярками, фильтр здесь только рискует молча срезать нужное.

**Действие:** Add Action → 🔍 (поиск в шапке) → ввести `HTTP` → выбрать
**HTTP Request** (не «HTTP Server Response» — это другое).

Экран действия разбит на вкладки **Settings / Query Params / Content
Body / Header Params**:

- **Settings:** Request method `POST`, Enter url —
  `https://<домен>/notification` (не `http://`, не tailnet-адрес).
  «Use authorization» и «Allow any certificate» — НЕ включать (не Basic
  Auth, и сертификат у нас настоящий от Let's Encrypt).
- **Header Params:** одна запись —
  `X-Auth-Token` → `<секрет из шага 2>`.
  (Content-Type задаётся отдельно на вкладке Content Body, не здесь.)
- **Content Body:** Content type — выбрать `application/json` из
  выпадающего списка. Content Body → переключатель **Text** (не File).
  В текстовое поле:

  ```
  {"package": "
  ```
  → тап **`...`** справа от поля → в списке переменных выбрать
  **Notification Package Name** → он вставится как переменная (не как
  обычный текст, будет выглядеть иначе, чем то, что печатал руками) →
  допечатать
  ```
  ", "title": "
  ```
  → **`...`** → **Notification Title** → допечатать
  ```
  ", "text": "
  ```
  → **`...`** → **Notification Text** (главное поле — там сумма и
  продавец) → допечатать закрывающее
  ```
  "}
  ```

  ⚠️ **Готовой переменной для времени уведомления в MacroDroid нет** — не
  искать, не выдумывать. Сервер её не требует (`posted_at` необязателен),
  так что поле просто отсутствует в теле — три переменные, не четыре.

  ⚠️ **Ничего не должно остаться после закрывающей `}`.** Живой баг:
  случайно вставленная лишняя переменная (`{popup_message_text}`) после
  `}` ломала весь JSON — сервер отвечал `400`, ничего не сохраняя даже
  в сырой лог (запись в `finance_raw.jsonl` происходит только после
  успешного разбора JSON, так что при этой ошибке не видно вообще ничего,
  ни одной строки, полная тишина). Если после теста лог пустой и в
  `finance_raw.jsonl` тоже пусто — в первую очередь проверяй именно это:
  не осталось ли мусора в поле Content Body.

Сохранить действие (галочка ✓), сохранить макрос, включить тумблер.

**Проверка без ожидания реальной покупки:** долгий тап на макрос в списке →
**System Log** (или значок истории). Там виден код ответа сразу после
теста: `200` — дошло и разобралось, `400` — проблема в теле запроса (см.
выше), другое — смотреть логи сервера через EDITH (`journalctl --user -u
hermes-finance-webhook` и, если Caddy нужен, `sudo journalctl -u caddy` —
это уже не выполнить через терминал EDITH без sudo-пароля, только через
прямой SSH).

Ответ сервиса говорит, что произошло: `recorded` (записано в таблицу),
`raw_only` (этап 1, только сохранено), `unparsed` (не разобралось, лежит на
разбор), `duplicate` (это уведомление уже видели).

Работает при любом состоянии VPN на телефоне — это и была вся цель смены
схемы.

## Дедуп

Android показывает одно и то же уведомление повторно — при обновлении,
перерисовке шторки, перезапуске MacroDroid. Без дедупа одна покупка легко
станет тремя строками. Отпечаток считается по пакету, тексту и времени с
точностью до минуты; хранится последние 2000 в `finance_seen.json`.

⚠️ На практике тело запроса от MacroDroid шлёт только пакет, заголовок и
текст — без времени (готовой переменной для времени уведомления в
MacroDroid нет, см. шаг 4 выше). Без `posted_at` отпечаток считается по
пакету и тексту без временной составляющей — дедуп всё ещё работает
(повтор той же покупки с тем же текстом схлопнется), просто чуть грубее:
две РАЗНЫЕ покупки с байт-в-байт одинаковым текстом уведомления (редкость)
задедупились бы как одна. Цена этого компромисса намного меньше, чем
цена охоты за несуществующей переменной.

Отдельно: при **ошибке записи в таблицу** отпечаток НЕ сохраняется — иначе
сбой сети означал бы навсегда потерянную трату. Повторная доставка
попробует записать снова.

## Файлы состояния (в профиле, не в git)

| Файл | Что |
|---|---|
| `finance_webhook.json` | конфиг: секрет, id таблицы, адрес, `raw_only` |
| `finance_rules.json` | правила «продавец → категория» |
| `finance_raw.jsonl` | все уведомления как пришли, всегда |
| `finance_unparsed.jsonl` | что не разобралось — на разбор EDITH |
| `finance_seen.json` | отпечатки для дедупа |

## Что осталось на потом

- **Еженедельный разбор неразобранного.** EDITH показывает накопившееся из
  `finance_unparsed.jsonl` пачкой, спрашивает, что это было, и дописывает
  правила в `finance_rules.json`. Одним вызовом модели на неделю.
- **Наличные и переводы между своими счетами** пушами не ловятся в
  принципе — это остаётся ручным вводом через EDITH, но таких трат мало.
