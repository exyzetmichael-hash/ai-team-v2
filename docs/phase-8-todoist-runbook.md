# Фаза 8 — Runbook: Todoist у секретаря

**Цель:** задачи Михаила живут в Todoist, и секретарь работает с ними напрямую — читает, ставит, закрывает, переносит сроки. Утренняя сводка учитывает задачи наравне с календарём.

**Что выбрано и почему:** официальный MCP-сервер от самого Doist (`@doist/todoist-mcp`, npm, версия 12.1.2 на момент написания) в stdio-режиме. У Hermes своей интеграции с Todoist нет — проверил по исходникам v0.19.0, там Todoist упоминается только как пример источника вебхуков. У Doist есть ещё хостед-вариант по HTTP с OAuth-авторизацией через браузер — он не подходит: сервер headless, браузера там нет.

---

## 1. Взять API-токен

Todoist → **Settings → Integrations → Developer → API token**. Скопируй.

Это персональный токен, дающий полный доступ к твоему аккаунту Todoist. Обращайся с ним как с паролем.

## 2. Положить токен в `.env` секретаря

**На сервере**, руками — не через чат с агентом:
```bash
echo 'TODOIST_API_KEY=<токен из шага 1>' >> ~/.hermes/profiles/secretary/.env
chmod 600 ~/.hermes/profiles/secretary/.env
```

⚠️ **Токен не должен попадать ни в `config.yaml`, ни в чат с агентом.** В конфиге стоит подстановка `${TODOIST_API_KEY}` — Hermes сам возьмёт значение из окружения в момент подключения к MCP-серверу. Конфиг лежит в git, секретам там не место; а всё, что написано в чат, уходит в промпт LLM-провайдера как обычный текст.

## 3. Обновить конфиг секретаря

```bash
cd ~/ai-team-v2 && git pull
cp profiles/secretary/config.yaml  ~/.hermes/profiles/secretary/config.yaml
cp profiles/secretary/SOUL.md      ~/.hermes/profiles/secretary/SOUL.md
cp profiles/secretary/MORNING.md   ~/.hermes/profiles/secretary/MORNING.md
sudo hermes -p secretary gateway restart
```

Что поменялось в этих файлах:
- **`config.yaml`** — добавлен `mcp_servers.todoist` с фильтром инструментов (см. ниже).
- **`SOUL.md`** — новый раздел «Задачи — Todoist, и только он»: смотреть в Todoist, а не вспоминать; переносить срок через `reschedule-tasks`, а не переписывать дату; не путать задачи с событиями календаря.
- **`MORNING.md`** — в утренний чеклист добавлен шаг с задачами: просроченные важнее сегодняшних, весь список не пересказывать.

## 4. Проверить, что сервер поднялся и инструменты видны

```bash
hermes -p secretary mcp list
hermes -p secretary mcp test todoist
```

`mcp test` должен подключиться и перечислить доступные инструменты.

### ⚠️ Про фильтр инструментов — тут возможна правка

Сервер отдаёт **~45 инструментов** (метки, фильтры, комментарии, воркспейсы, аналитика продуктивности). Секретарю нужна десятая часть, а каждая лишняя схема — это токены в **каждом** ходу плюс лишний шум при выборе инструмента для дешёвой модели. Поэтому в конфиге стоит `tools.include` из девяти:

`find-tasks`, `find-tasks-by-date`, `find-completed-tasks`, `add-tasks`, `update-tasks`, `complete-tasks`, `reschedule-tasks`, `find-projects`, `get-overview`

**Честно:** имена я взял из наблюдаемого набора инструментов этого сервера, но точную сверку с той версией, что установится у тебя, не делал — версии могут расходиться. Если после `mcp test` инструментов **меньше девяти или нет вообще** — значит имена разошлись. Тогда:

```bash
# посмотреть реальные имена, которые отдаёт сервер
hermes -p secretary mcp test todoist
```
и либо поправь список `include` в `~/.hermes/profiles/secretary/config.yaml` под реальные имена, либо **временно закомментируй весь блок `tools:`** — тогда подключатся все инструменты (рабочий вариант, просто дороже по токенам). Пришли мне список имён — приведу конфиг в порядок в репозитории.

## 5. Живой тест

```bash
hermes -p secretary
```

**Чтение:**
```
Что у меня сегодня по задачам?
```
→ должен реально сходить в Todoist, а не «вспомнить». Проверь, что названия задач совпадают с приложением.

**Создание:**
```
Поставь задачу: отправить документы в вуз, на завтра.
```
→ задача должна появиться **в приложении Todoist**, а не только в ответе.

**Перенос (важный кейс):**
```
Перенеси эту задачу на пятницу.
```
→ должен использовать `reschedule-tasks`. Если у задачи была повторяемость — она должна сохраниться.

**Закрытие:**
```
Закрой задачу про документы.
```

**Утренняя сводка** — прогони вручную, не дожидаясь утра:
```bash
hermes -p secretary cron list          # найди job_id "Утренней сводки"
hermes -p secretary cron run <job_id>
```
→ в сводке должны появиться задачи. Если задач и событий нет вообще — придёт `[SILENT]`, то есть ничего, это по-прежнему нормально.

---

## На что смотреть в первую неделю

- **Не завёл ли секретарь параллельный список.** Спроси «какие у меня задачи» дважды в разных сессиях — ответ должен браться из Todoist оба раза, а не из памяти. Если начнёт «помнить» задачи вместо чтения — скажи, ужесточим формулировку в SOUL.
- **Повторяющиеся задачи.** Самый вероятный баг: перенос через `update-tasks` вместо `reschedule-tasks` убивает повторяемость. Проверь на реальной регулярной задаче.
- **Объём утренней сводки.** Если начнёт вываливать весь Todoist простынёй — правим `MORNING.md`.
- **Задача vs событие.** Просьба «напомни завтра позвонить» — это задача или событие в календаре? Секретарь должен выбирать осмысленно, а не дублировать в оба места.
